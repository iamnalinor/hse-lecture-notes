# Проверка чата на production

Сайт: https://hse.nalinor.dev. API: https://hse-lecture-notes-api.nalinor.workers.dev.

Этот документ описывает ожидаемое поведение. Фактические версии выпуска, результаты автоматических проверок и smoke фиксируются в отчёте релиза.

## Порядок выпуска

1. Проверить свежие Worker version, D1 policy, расходы/reserves и отсутствие старых running runs. Сохранить приватный baseline вне Git.
2. Установить Worker secret `OPENAI_API_KEY` из уже согласованного корневого env-файла через stdin. Значение ключа не печатать и не передавать аргументом команды.
3. Применить additive D1 migration, затем выпустить backend с явным `LLM_PROVIDER=openai` и стандартным OpenAI base URL. Проверить backend smoke до публикации frontend. OAuth/proxy Codex не используются на этом маршруте.
4. Частичным admin patch установить 15 сообщений / 50 000 символов / 8 раундов / 16 исполненных вызовов / 60 000 символов результатов / $15 за 7 дней. Прочие квоты, модели, effort, тарифы и накопленные расходы сохраняются. Прочитать policy обратно; bootstrap JSON не заменяет production patch.
5. Выпустить frontend после backend. Один общий push в main не обеспечивает порядок двух независимых CI workflows: использовать отдельные последовательные releases либо уже подтверждённый backend до запуска frontend workflow.
6. Проверить фактически активные версии и сценарии ниже. Для нового frontend выполнить полную перезагрузку и принять обновление service worker, если показана соответствующая плашка.

## Проверки в браузере

| Сценарий | Действия | Ожидаемый результат |
| --- | --- | --- |
| Первый ответ | Создать новый чат, спросить «Почему производная x в квадрате равна 2x?» | Короткое название появляется до текста ответа, затем приходит ответ. В ответе нет строки «Название:», JSON метаданных или служебного вызова |
| Название по ходу чата | Затем явно сменить задачу: «Теперь вместо производных готовимся к контрольной по делимости» | При существенной смене цели модель может обновить название; обычное уточнение не требует переименования |
| Саджест | Дождаться ответа, оставить поле пустым | Если модель предложила продолжение, в placeholder — короткая реплика пользователя, обычно 3–7 слов, без Markdown, обратных кавычек, TeX и переносов. При отсутствии предложения остаётся обычный placeholder |
| Tab | Нажать Tab при пустом поле и видимом саджесте | Реплика вставляется в draft, запрос не отправляется. После очистки принятого текста тот же саджест не появляется вновь в этой сессии |
| Обычная клавиатура | Проверить Shift+Tab, ввод через IME, Tab с непустым draft и Enter при одном placeholder | Shift+Tab сохраняет переход фокуса, IME не прерывается, draft не заменяется, placeholder сам не отправляется |
| Touch | Открыть чат на телефоне | Саджест только в placeholder. Нет кнопки «Вставить» и принятия касанием поля |
| Цитата | Выделить текст конспекта/ответа/агентского блока, выбрать «Спросить ИИ» | Кнопка не мелькает в левом верхнем углу. Цитата видна в composer; старый саджест скрыт и не заменяет вопрос |
| Выделение | Тройной клик по абзацу с формулой в пользовательском и ассистентском сообщении | Выделяется весь видимый абзац, а не только часть между формулами |
| Длинный чат | Задать 8 коротких вопросов с ответами в одном чате; предел размера может наступить раньше | При 15 логических сообщениях, включая текущий вопрос, появляется «Чат слишком длинный, качество снижено. Рекомендуем создать новый чат». Продолжать можно; в модели используется low |
| Сохранение ограничения | Перезагрузить длинный чат, повторить последний ответ, перейти в другой короткий/новый чат | Ограничение сохраняется у длинного thread. Новый чат имеет обычный маршрут; default/guest и так используют low, student/extended могут получить high при доступной квоте |
| Default и два статуса | Открыть длинный чат под default-аккаунтом, затем получить rate limit | Один основной статус: сначала rate limit, после его таймера — длинный чат. Длинное предложение войти как студент не дублируется; имя и «Сменить аккаунт» остаются компактной строкой |
| Блокировка отправки | При исчерпанном лимите/недоступности открыть composer с draft | Видна причина недоступности, draft сохраняется. Подпись длинного чата не дублирует блокирующую плашку |
| Stop | Начать ответ, остановить после появления текста | Текст доступен, нет нового саджеста; уже опубликованное название сохраняется, видна подпись «Ответ остановлен» |
| Обрыв/reconnect | Разорвать соединение во время ответа, восстановить и открыть чат | Обычный обрыв сокета не отменяет серверный запуск. История восстанавливает его сохранённые текст, название и саджест; повтор того же clientRequestId не списывается заново |
| Поздний ответ | Во время генерации переключить чат/аккаунт и начать draft | Поздние события старого запроса не заменяют draft, название или саджест текущего чата |
| Повтор ответа | Повторить последний ответ | Прежний саджест скрыт во время генерации. При новом успешном ответе появляется только его предложение; старые ответы повторять нельзя |
| Вход после лимита | Под гостем отправить вопрос до отказа квоты, затем войти | Этот вопрос автоматически отправляется один раз в исходный чат, без второго экземпляра и без оставшегося черновика. Изменённый черновик, неуспешный вход и переход на другую страницу во время входа не запускают старый вопрос |
| Мобильная шапка | Проверить 390, 320 и 280 px | При наличии места видны поле «Поиск», «Чат» и тема; первым сворачивается поиск, подпись «Чат» сохраняется. Поиск открывается, Escape возвращает фокус |
| Размер саджеста | Дождаться длинного допустимого саджеста при пустом поле, изменить ширину окна | Placeholder виден полностью в пределах высоты composer, без обрезанной второй строки |
| История чатов | Открыть историю, нажать снаружи; снова открыть и нажать Escape | Меню закрывается; Escape возвращает фокус на кнопку истории и оставляет панель чата открытой. Клик внутри/выбор чата работает |
| Скроллбары | Прокрутить страницу, длинную историю и поле ввода в обеих темах | Тонкий скруглённый серый ползунок, прозрачная дорожка; цвета соответствуют теме. На touch отображением native scrollbar может управлять ОС |
| Большой объём чтения | Задать вопрос, требующий нескольких источников, раскрыть шаги | Видны только поиск и чтение, без служебной строки «Лимит инструментов». При исчерпании доступного объёма модель завершает ответ по уже найденному |
| Квиз | Открыть квиз по О-символике, первую и следующие многочастные задачи | Общая часть отдельным абзацем, каждый подпункт условия и ответа — отдельной строкой |
| Главная и статусы | Открыть главную и запустить проверку браузера | Удалённая подпись «ПИ ФКН ВШЭ · первый курс · 2026/27» не показывается; статус — «Проверяю браузер…» |

Проверить desktop 1280 px и mobile 390 px в светлой/тёмной темах. В DevTools WebSocket frames и восстановленной HTTP history разрешены публичные title/suggestion, но отсутствуют `set_topic`, `suggest_reply`, их arguments/ack/validation errors, raw reasoning и служебные context items. Поиск/чтение остаются обычными видимыми шагами.

## Сбои модели и учёт

Не ломать production endpoint ради искусственной ошибки. Regression tests покрывают неожиданные output items, неверные/повторные call ID, первый ответ без темы, неправильные аргументы, слишком большой саджест, служебный вызов без текста и усечённый/пустой результат чтения.

Полный текст ответа принимается без саджеста. Невалидный или слишком большой саджест отбрасывается. Первый вызов темы обязателен и скрыт; если он невалиден, запуск завершается понятной ошибкой. Только служебный вызов без ответа может продолжиться в оставшихся обычных раундах; принудительного end_turn и корректирующего запроса нет. Ответы с раздельными текстовыми сообщениями разделяются абзацами. Ошибка, таймаут и обрыв соединения имеют разные безопасные пояснения с кодом, которые одинаковы сразу и после перезагрузки; пустой incomplete тоже видим и допускает повтор.

В admin-диагностике после smoke проверить provider=openai, соответствие model/effort/quota bucket и рост input/cached/write/output tokens и стоимости. Повторные finalize и reconnect не добавляют повторное списание; usage сохраняется даже у incomplete. При отсутствии usage расход оценивается отдельно для каждого неизвестного раунда, с uncertain flag.

Кэш проверяется по фактическому cached/write usage на нескольких последовательных вопросах. Попадание не гарантируется на каждом запросе; сдвиг окна может менять префикс. Полную бесконечную историю ради кэша не отправляем.

## Откат

Сначала использовать совместимую предыдущую Worker version или явный Codex route; не включать скрытый автоматический fallback. Новые D1 столбцы и сохранённую историю не удалять. Бюджет $15, накопленные расходы и лимиты 15 / 50k сохраняются. Frontend обрабатывает отсутствие новых полей при совместимом откате. Зафиксировать выбранный provider в конфигурации, чтобы следующий CI deploy не изменил его случайно.
