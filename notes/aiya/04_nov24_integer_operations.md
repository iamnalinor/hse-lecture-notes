# Контекст

На прошлой лекции разобраны классы памяти (определение [-@def:lec03:storage-class]) и базовые типы C: целые типы с их минимальными гарантированными размерами, знаковость, `char`, `bool`, представление целых в памяти (порядок байтов, дополнительный код) и четыре категории поведения, которые различает стандарт: определенное, определяемое реализацией, неуточненное и неопределенное. Эта лекция начинается с переменных: где видно имя переменной, как это связано с классом памяти и что лежит в переменной, которой не дали начального значения. Дальше — как записывать значения в программе (литералы) и что с ними можно делать: арифметика, сравнения, логические операции, присваивания, а затем условная и поразрядные операции, приведение типов, `printf` и `scanf`. Почти каждая операция таит ловушку, которая следует из устройства типов: деление отрицательных чисел, переполнение, смешение знаковых и беззнаковых операндов, порядок побочных эффектов.

# После прочтения ты сможешь

- предсказать, что напечатает программа с глобальными, локальными и `static`-переменными, в том числе с одинаковыми именами;
- назвать начальное значение переменной без инициализатора по её классу памяти;
- найти значение и тип целой или символьной константы: десятичной, восьмеричной, шестнадцатеричной, двоичной, с суффиксом и без;
- вычислить `/` и `%` с отрицательными операндами и получить остаток из $[0, b)$;
- отличить определенное беззнаковое переполнение от неопределенного знакового и найти в выражении неопределенное поведение;
- вычислить логическое выражение с `&&`, `||`, `!` с учетом ленивого вычисления и побочных эффектов;
- записать условием принадлежность числа промежутку, а через `?:` — модуль и максимум;
- проследить значения переменных после `++`, `--`, составного присваивания и запятой;
- найти выражение, в котором одна переменная меняется дважды без точки следования;
- записать маской установку, сброс, инверсию и проверку бита или группы битов;
- проверить поразрядными операциями, что число — степень двойки;
- найти тип и значение выражения со смешанными типами по правилам целочисленного продвижения и обычных арифметических преобразований;
- поставить явное приведение так, чтобы деление целых выполнялось как вещественное;
- подобрать спецификатор `printf` и `scanf` к типу и проверить, удалось ли прочитать ввод.

# Теория

## Переменные {#sec:lec04:variables}

### Объявление

Пока в программе нет массивов, структур и указателей, единственный способ добраться до ячейки памяти — дать ей имя. Имя, привязанное к ячейке, и есть переменная. Компилятору мало знать имя: чтобы прочитать значение, нужно знать, сколько байтов взять и как их понимать, поэтому у переменной всегда есть тип. В C он известен до запуска программы и не меняется (*статическая типизация*), и часть ошибок, например обращение к переменной как к значению другого типа, компилятор находит заранее. В Python тип связан со значением и может меняться при работе программы: гибкости больше, но такие ошибки всплывают только при запуске.

::: {.definition #def:lec04:variable title="переменная"}
*Переменная* — именованный объект программы: тип, имя и значение. *Объявление переменной* — запись `тип имя;` или `тип имя1, имя2, …;`, перед ней можно указать класс памяти (`static`, `register`), а после имени — начальное значение: `int a, b; unsigned c = 21749;`. Ключевые слова языка (`int`, `if`, `return` и другие; в C89 их 32, в C99 добавлено еще 5) именами переменных быть не могут.
:::

### Область действия и класс памяти

У переменной два независимых свойства. Класс памяти (определение [-@def:lec03:storage-class]) говорит, где лежит переменная и когда живет. Область действия говорит, где в тексте программы её имя известно компилятору.

::: {.definition #def:lec04:scope title="область действия"}
*Область действия* (scope, область видимости) имени — часть текста программы, в которой этим именем можно пользоваться. Переменная может быть объявлена:

1. внутри функции или блока `{ … }` — *локальная*; область действия — от строки объявления до конца блока;
2. в заголовке функции — *параметр*; область действия — тело функции;
3. вне всех функций — *глобальная*; область действия — от строки объявления до конца файла.

В одной области действия нельзя объявить две переменные с одним именем.
:::

Легко решить, что одно свойство задает другое: глобальная переменная статическая, значит, и локальная обязана быть автоматической. Первая половина верна. Глобальная переменная не принадлежит ни одной функции, поэтому привязать её память к вызову функции нельзя, и класс памяти у неё только статический. А вот локальная переменная бывает любой:

| Где объявлена | Как | Класс памяти | Где видно имя |
| --- | --- | --- | --- |
| вне функций | `int x;` | статический | от объявления до конца файла |
| в функции | `int y;` | автоматический (по умолчанию) | от объявления до конца блока |
| в функции | `static int z;` | статический | от объявления до конца блока |
| в функции | `register int r;` | регистровый (подсказка) | от объявления до конца блока |

Локальная статическая переменная `z` из третьей строки сочетает оба свойства. Имя её видно только внутри функции, и чужой код её не испортит. Память же у неё статическая: она выделяется один раз до начала `main`, инициализируется тоже один раз и сохраняет значение между вызовами функции.

::: {.example #ex:lec04:static-local title="счетчик между вызовами"}
```c
#include <stdio.h>

int next_id(void)
{
    static int id = 100;    /* статическая память, имя видно только здесь */
    int step = 1;           /* автоматическая: заново при каждом вызове */
    id += step;
    return id;
}

int main(void)
{
    int a = next_id();
    int b = next_id();
    int c = next_id();
    printf("%d %d %d\n", a, b, c);    /* 101 102 103 */
    return 0;
}
```

`id` получает значение $100$ один раз, до первого вызова, и каждый вызов прибавляет к нему единицу. `step` создается при каждом входе в `next_id` и каждый раз равна $1$. Если убрать `static`, `id` станет автоматической: каждый вызов заново начнет со $100$, и программа напечатает `101 101 101`.
:::

Типичное применение — однократная инициализация данных, которые нужны одной функции. В функции заводят `static int initialized = 0;`, при входе проверяют флаг и, если он нулевой, выполняют подготовку и записывают в него $1$. Следующие вызовы подготовку пропускают, потому что флаг пережил предыдущий вызов. Глобальную переменную ради этого заводить не нужно: все глобальные переменные программы лежат в одном пространстве имен, и чем их меньше, тем меньше мест, где их можно испортить.

Слово `static` перед глобальной переменной (`static int mult = 0;` вне функций) класс памяти не меняет: он и так статический. Оно прячет имя от других файлов программы, когда программа собирается из нескольких файлов. Как файлы связываются в одну программу, разберем, когда дойдем до компоновки.

::: {.remark #rem:lec04:auto-keyword tag="корнер-кейс"}
Автоматический класс памяти тоже можно указать явно словом `auto`: `auto int y;`. Так никто не писал, потому что внутри функции это и так умолчание. В C++ слово `auto` давно означает другое: тип переменной выводится из инициализатора. В C23 это значение пришло и в C: `auto x = 2.5;` объявляет `x` типа `double`. Сломать старые программы это не могло, потому что старым смыслом `auto` почти никто не пользовался.
:::

Если две переменные с одним именем объявлены в разных областях действия и эти области пересекаются, возникает неоднозначность: к какой из них относится имя. Компьютер неоднозначностей не допускает, и язык обязан выбрать правило. В C внутренняя область действия *затеняет* внешнюю: имя относится к самой внутренней из видимых переменных.

::: {.example #ex:lec04:scope-classes title="классы памяти и области действия"}
```c
#include <stdio.h>

int count;              /* глобальная: статическая память */

void func(void)
{
    int count;          /* локальная: автоматическая память */
    count = count - 2;
}

static int mult = 0;    /* глобальная, имя скрыто от других файлов */

int sum(int x, int y)
{
    count++;
    return (x + y) * (++mult);
}

int main(void)
{
    register int s = 0; /* подсказка: держать в регистре */
    count = 0;
    s += sum(5, 7);
    func();
    printf("Sum is %d, func is called %d times\n", s, count);
    return 0;
}
```

Внутри `func` имя `count` означает локальную переменную, и глобальную `count` функция не меняет. `sum` своей `count` не имеет и увеличивает глобальную. Поэтому программа печатает `Sum is 12, func is called 1 times`: $(5 + 7) \cdot 1 = 12$, а глобальный `count` изменила только `sum`. Строка `count = count - 2;` в `func` читает локальную переменную, которой ничего не присвоено, и это ошибка (раздел ниже); `gcc -Wall` предупреждает: `'count' is used uninitialized`.
:::

Затенение — не единственный возможный ответ. В языках с классами к внешнему имени можно обратиться по длинному имени (как `this.count` в Java). Можно и вовсе запретить совпадение имен: если локальная переменная затеняет глобальную, это чаще всего ошибка проектирования, и пусть она обнаружится при компиляции. В C затенение разрешено, но GCC с ключом `-Wshadow` (он не входит в `-Wall -Wextra`) предупреждает о каждом таком месте.

### Инициализация

Объявление выделяет ячейку нужного размера в своем классе памяти. Значение в неё нужно сначала записать и только потом читать. Если указан инициализатор (`int x = 42;`), вопросов нет: автоматическая переменная получает значение при каждом входе в блок, статическая — один раз, к началу работы программы. Вопрос в том, что лежит в переменной без инициализатора.

::: {.definition #def:lec04:initialization title="начальное значение без инициализатора"}
- Статические переменные (глобальные и `static` в функциях) без инициализатора обнуляются: у целых значение $0$, у вещественных $0{,}0$.
- Значение автоматической переменной без инициализатора *не определено*. Чтение такой переменной до первой записи — ошибка в программе.
:::

Почему правила разные. Безопасный язык обнулял бы и автоматические переменные: тогда неинициализированное чтение невозможно. Для статической памяти обнуление стоит дешево: оно делается один раз при запуске программы. Автоматическую память пришлось бы обнулять при каждом вызове функции, даже если программист сразу же запишет туда свое значение, и отказаться от этой работы было бы нельзя. C не навязывает программисту расходов, которых тот не может избежать, и выбирает скорость: инициализировать автоматическую переменную — забота программиста.

::: {.remark #rem:lec04:uninitialized tag="подводный камень"}
*Неинициализированное чтение* (uninitialized read) — одна из опасных ошибок: в ячейке лежат остатки того, что было там раньше, например данные предыдущей вызванной функции. Программа может годами работать правильно и сломаться при другом компиляторе или ключе оптимизации; через такие ошибки атакуют программы, если содержимое памяти можно подстроить извне. `gcc -Wall` находит простые случаи (`is used uninitialized`), но не все, поэтому локальные переменные лучше инициализировать сразу при объявлении.
:::

Еще два правила понадобятся позже. Глобальная переменная, общая для нескольких файлов, инициализируется только в том файле, где она определена. Переменная, объявленная с `const` (`const int n = 10;`), — константа: её значение задается при инициализации и потом не меняется, попытка присвоить ей — ошибка компиляции.

## Литералы

Чтобы дать переменной начальное значение, его нужно записать в тексте программы. В программе на прошлой лекции такие записи уже были: `0` в `return 0;`, строка `"Hello, world\n"`. Значение, записанное прямо в тексте программы, называется литералом. У литерала, как у переменной, есть тип, и от типа зависит, как с ним будут считать: `7 / 2` и `7.0 / 2` дают разные результаты (дальше в лекции это `3` и `3.5`). Поэтому сначала нужно научиться читать тип прямо по записи константы.

::: {.definition #def:lec04:literal title="литерал"}
*Литерал* (константа) — запись фиксированного значения в тексте программы. В C есть целые, вещественные, символьные и строковые литералы; тип литерала определяется его записью: системой счисления, суффиксом, кавычками.
:::

### Целые константы

Целую константу можно записать в четырех системах счисления:

| Запись | Система | Пример | Значение |
| --- | --- | --- | --- |
| без префикса, первая цифра не `0` | десятичная | `42` | $42$ |
| префикс `0` | восьмеричная | `052` | $5 \cdot 8 + 2 = 42$ |
| префикс `0x` или `0X` | шестнадцатеричная | `0x2A` | $2 \cdot 16 + 10 = 42$ |
| префикс `0b` или `0B` (C23) | двоичная | `0b101010` | $32 + 8 + 2 = 42$ |

Системы с основанием — степенью двойки нужны потому, что C работает с битами: поразрядные операции — самые быстрые на машине, и маски для них удобно писать так, чтобы цифра соответствовала группе бит. Двоичная запись слишком длинная, поэтому чаще всего пишут шестнадцатеричную: одна цифра — ровно четыре бита, `0xFF` — восемь единиц. Восьмеричная цифра — три бита; она пришла из Unix, где права доступа к файлу — три тройки бит «чтение, запись, выполнение» для владельца, группы и остальных: `0755` — это $111\,101\,101_2$, все права владельцу, чтение и выполнение остальным. Двоичных констант долго не было вовсе, они появились только в C23.

В C23 длинную константу можно разбить апострофами: `1'000'000` — то же, что `1000000`, `0xFF'FF` — то же, что `0xFFFF`. Апостроф только облегчает чтение и на значение не влияет.

```c
#include <stdio.h>

int main(void)
{
    printf("%d %d %d %d\n", 42, 052, 0x2A, 0b101010); /* 42 42 42 42 */
    printf("%d %d\n", 1'000'000, 0xFF'FF);            /* 1000000 65535 */
    return 0;
}
```

::: {.remark #rem:lec04:octal-zero tag="подводный камень"}
Ведущий ноль меняет систему счисления. Выравнивая числа в столбик, легко написать `012` вместо `12`, и это будет восьмеричное $10$: `012 + 1` равно `11`. В восьмеричной записи нет цифр `8` и `9`, поэтому `09` — ошибка компиляции, а не девять. Сам `0` формально восьмеричная константа, но значение у неё одно и то же в любой системе.
:::

Тип константы задают *суффиксы*: `u` или `U` — беззнаковая, `l` или `L` — `long`, `ll` или `LL` — `long long`; их можно сочетать в любом порядке и регистре (`1000U`, `999llu`, `10UL`). Если суффикса нет, константа получает первый тип из списка, в который помещается её значение:

| Суффикс | Десятичная константа | Восьмеричная, шестнадцатеричная, двоичная |
| --- | --- | --- |
| нет | `int`, `long`, `long long` | `int`, `unsigned int`, `long`, `unsigned long`, `long long`, `unsigned long long` |
| `u` | `unsigned int`, `unsigned long`, `unsigned long long` | так же |
| `l` | `long`, `long long` | `long`, `unsigned long`, `long long`, `unsigned long long` |
| `ul` | `unsigned long`, `unsigned long long` | так же |
| `ll` | `long long` | `long long`, `unsigned long long` |
| `ull` | `unsigned long long` | так же |

Почему для шестнадцатеричных в списке есть беззнаковые типы, а для десятичных нет: шестнадцатеричной записью обычно задают битовые маски, и `0xFFFFFFFF` («все 32 бита — единицы») естественно считать `unsigned int`, а не переходить к 8-байтовому `long`. Целых чисел произвольной длины в C нет: если значение не помещается даже в последний тип списка, константа ошибочна (Clang такую программу не компилирует, GCC предупреждает `integer constant is too large for its type`).

::: {.example #ex:lec04:literal-types title="тип константы зависит от записи"}
Пусть `int` занимает 4 байта, `long` — 8 (так на 64-битном Linux, где мы проверяем примеры). Тогда $2^{31} - 1 = 2147483647$ — наибольшее значение `int`.

- `2147483647` — `int`;
- `2147483648` — не помещается в `int`, следующий в списке для десятичной константы `long`: `sizeof 2147483648` равно `8`;
- `0x80000000` — то же значение $2^{31}$, но шестнадцатеричное: следующий в списке `unsigned int`, `sizeof 0x80000000` равно `4`.

Одно и то же число $2^{31}$ в двух записях получает типы разной ширины и знаковости.
:::

::: {.remark #rem:lec04:no-negative-literals tag="корнер-кейс"}
Отрицательных целых литералов в C нет. `-34l` — это одноместный минус, примененный к константе `34l` типа `long`. Обычно разницы не видно, но на границе типа она есть: `-2147483648` при 4-байтовом `int` и 8-байтовом `long` имеет тип `long` (при 4-байтовом `long` — `long long`), потому что сама константа `2147483648` в `int` не помещается. Поэтому наименьшее значение `int` в `limits.h` записывают выражением вроде `(-2147483647 - 1)`, а в программе берут готовое имя `INT_MIN`.
:::

### Символьные константы

Символьная константа — символ в одинарных кавычках: `'A'`, `'7'`, `'\n'`. Её значение — код символа в кодировке, которой пользуется программа. В ASCII `'A'` имеет код $65$, `'0'` — $48$, `'*'` — $42$. Так символьный тип и сводится к целому: символ хранится как число, а печатать его буквой или числом, решает спецификатор вывода.

Внутри одинарных кавычек работают те же управляющие последовательности, что в форматной строке `printf` (`'\n'`, `'\t'`, `'\\'`), и еще `'\''` — апостроф, `'\b'` — шаг назад, `'\0'` — символ с кодом $0$. Любой код можно задать числом: восьмеричным (`'\101'`, от одной до трех цифр) или шестнадцатеричным (`'\x41'`); обе записи дают `'A'`.

::: {.remark #rem:lec04:char-literal-int tag="частое заблуждение"}
*«`'A'` имеет тип `char`, значит, `sizeof 'A'` равно 1».* В C тип обычной символьной константы — `int`, поэтому `sizeof 'A'` равно `sizeof(int)`, то есть `4` на нашей машине; `sizeof(char)` при этом всегда `1`. В C++ тип `'A'` — `char`, и там ответ `1`; на этом месте программы на двух языках расходятся.
:::

```c
#include <stdio.h>

int main(void)
{
    printf("%d %c %d\n", 'A', 65, '\n');             /* 65 A 10 */
    printf("%zu %zu\n", sizeof 'A', sizeof(char));    /* 4 1 */
    return 0;
}
```

### Вещественные и строковые константы

Константа с точкой или порядком — вещественная: `1.0`, `4.56e-4` (это $4{,}56 \cdot 10^{-4}$). Без суффикса её тип `double` (точности `float` для умолчания мало), суффикс `f` или `F` дает `float`, `l` или `L` — `long double`: `11.123F`, `3.1415926L`. Бывают и шестнадцатеричные вещественные константы, у которых порядок — степень двойки после `p`: `0x3.ABp3` $= 3\frac{171}{256} \cdot 2^3 = 29{,}34375$. Как устроены вещественные числа, разберем отдельно. Пока важно одно: `2.0` и `2` — константы разных типов, и в выражении это меняет результат (раздел [-@sec:lec04:conversions]).

Строковая константа — символы в двойных кавычках: `"a"`, `"Hello, world"`. `"a"` и `'a'` — разные вещи: первое — строка (массив символов, о них позже), второе — число $97$.

## Операции над целыми

Три слова, которые в C легко перепутать, — операция, выражение и оператор.

::: {.definition #def:lec04:expression title="операция, выражение, оператор"}
*Операция* — знак, задающий вычисление над операндами: `+`, `=`, `<<`. У операции есть *арность* (число операндов: одноместный минус `-x`, двухместное сложение `a + b`, трехместная условная операция `c ? x : y`), приоритет и ассоциативность. *Выражение* — имя переменной, константа, вызов функции или операция над выражениями. У выражения есть значение и тип; кроме того, его вычисление может менять состояние программы, это побочный эффект (о нём ниже). *Оператор* — конструкция, которая выполняется: выражение с точкой с запятой (`x = 2 + 3;`), блок `{ … }`, `if`, `while`, `return`. Значения и типа у оператора нет.
:::

Русские названия сбивают с толку: английское *operator* — это «операция», а «оператор» по-русски — *statement*.

### Арифметика, деление и остаток

Арифметические операции: одноместные `-` (смена знака) и `+`, двухместные `+`, `-`, `*`, `/` (деление нацело) и `%` (остаток от деления нацело). С неотрицательными числами `/` и `%` дают школьные частное и остаток: `7 / 2` равно `3`, `7 % 2` равно `1`. Вопрос, что происходит с отрицательными: у $-7$ при делении на $2$ «математический» остаток $1$ ($-7 = -4 \cdot 2 + 1$), а можно считать $-7 = -3 \cdot 2 - 1$.

Сначала о том, когда деление вообще целое. Сложение, вычитание и умножение целых дают целое, а деление выводит из целых чисел: $5 / 2 = 2{,}5$. Нужны обе операции, и вещественное деление, и деление нацело. Многие языки заводят для них два разных знака: в Pascal это `/` и `div`, в Python — `/` и `//`. В C знак один, а тип результата определяют типы операндов: если оба операнда целые, деление целое, `5 / 2` равно `2`. Чтобы получить $2{,}5$, вещественным делают хотя бы один операнд: `5.0 / 2` (подробнее — в разделе [-@sec:lec04:conversions]).

::: {.definition #def:lec04:division title="деление нацело и остаток"}
Для целых `a` и `b` при `b != 0` частное `a / b` — математическое частное $a / b$ с отброшенной дробной частью (*округление к нулю*, с C99). Остаток определяется так, чтобы выполнялось тождество
$$(a / b) \cdot b + a \,\%\, b = a.$$ {#eq:lec04:div-identity}
Отсюда остаток либо равен $0$, либо имеет знак делимого `a`, и $|a \,\%\, b| < |b|$.
:::

Почему так: округление к нулю дает `-a / b == -(a / b)` (частное меняет знак вместе с делимым), и так делят большинство процессоров. Тождество [-@eq:lec04:div-identity] нужно, чтобы по частному и остатку восстанавливалось делимое, иначе пара `/`, `%` теряет смысл.

::: {.example #ex:lec04:negative-division}
| `a` | `b` | `a / b` | `a % b` | проверка [-@eq:lec04:div-identity] |
| --- | --- | --- | --- | --- |
| $7$ | $2$ | $3$ | $1$ | $3 \cdot 2 + 1 = 7$ |
| $-7$ | $2$ | $-3$ | $-1$ | $-3 \cdot 2 - 1 = -7$ |
| $7$ | $-2$ | $-3$ | $1$ | $-3 \cdot (-2) + 1 = 7$ |
| $-7$ | $-2$ | $3$ | $-1$ | $3 \cdot (-2) - 1 = -7$ |

Знак остатка везде совпадает со знаком делимого.
:::

::: {.remark #rem:lec04:odd-check tag="подводный камень"}
Проверка нечетности `x % 2 == 1` неверна для отрицательных `x`: `-7 % 2` равно `-1`, и $-7$ окажется «четным». Правильно `x % 2 != 0`. Если нужен математический остаток из $[0, b)$ при $b > 0$ (номер дня недели, индекс в кольцевом буфере), его получают выражением `(a % b + b) % b`: для `a = -17`, `b = 5` это `(-2 + 5) % 5`, то есть `3` (если `b` может превышать `INT_MAX / 2`, сложение `a % b + b` способно переполниться при `a > 0`, и надежнее `int r = a % b; r < 0 ? r + b : r`).
:::

::: {.remark #rem:lec04:div-zero tag="корнер-кейс"}
Деление и остаток на ноль, `a / 0` и `a % 0`, — неопределенное поведение. Еще один крайний случай — `INT_MIN / -1`: математическое частное $2^{31}$ не помещается в 32-битный `int`, это переполнение; по стандарту в этом случае неопределены и `/`, и `%`.
:::

### Переполнение

Целые типы имеют фиксированный размер, потому что АЛУ складывает числа фиксированной ширины. Значит, у каждого типа есть наибольшее и наименьшее значения (их имена — в `limits.h`: `INT_MAX`, `INT_MIN`, `UINT_MAX`, …), и результат операции может за них выйти. Для беззнаковых и знаковых типов стандарт решает это по-разному.

::: {.definition #def:lec04:overflow title="переполнение"}
- Вычисление над *беззнаковыми* операндами никогда не переполняется: результат, который не помещается в тип, берется по модулю $2^N$, где $N$ — число бит типа («пропадают старшие биты»). Например, при 32-битном `unsigned` `UINT_MAX + 1u` равно `0`, а `0u - 1` равно `UINT_MAX`, то есть $4294967295$.
- Если результат операции над *знаковыми* операндами математически не определен или не помещается в тип, это *знаковое переполнение* — неопределенное поведение. Например, `INT_MAX + 1`, `-INT_MIN`, `INT_MIN / -1`.
:::

Почему так асимметрично. Беззнаковая арифметика по модулю $2^N$ на всех машинах одна и та же, и стандарт её гарантирует. Знаковые числа исторически хранились по-разному (прямой, обратный, дополнительный код), и результат переполнения на разных машинах отличался; стандарт не стал его фиксировать. С C23 дополнительный код обязателен, но переполнение осталось неопределенным: на это опираются оптимизирующие компиляторы.

Компилятор вправе считать, что переполнения в программе нет, и оптимизировать её из этого расчета. Функцию `return x + 1 > x;` GCC с `-O2` компилирует в `return 1`, и для `x = INT_MAX` она возвращает `1`, а не «переполненный» `0`. Поэтому переполнение проверяют до операции, а не после: `x < INT_MAX`, а не `x + 1 > x`. Для суммы двух `int` проверка выглядит так (вычитание в ней переполниться не может):

```c
int a = 2000000000, b = 2000000000;
int bad = (b > 0 && a > INT_MAX - b) || (b < 0 && a < INT_MIN - b); /* 1 */
```

В C23 для этого есть `ckd_add(&r, a, b)` из `stdckdint.h` (в GCC с версии 14, в Clang с версии 18): она записывает результат в `r` (при переполнении — усеченный по модулю $2^N$) и возвращает `true` (`1`), если сумма в тип `r` не поместилась, и `false` (`0`) иначе. В более старых GCC и Clang то же делает встроенная функция `__builtin_add_overflow(a, b, &r)`.

Тип, в котором выполняется операция, определяют операнды, а не переменная, куда пойдет результат. В `long long t = 2000000000 * 2;` перемножаются два `int`, и переполнение происходит раньше, чем значение попадет в `t`. Чтобы считать в широком типе, широким делают операнд: `2000000000LL * 2` равно $4000000000$.

::: {.remark #rem:lec04:ubsan}
Найти неопределенное поведение при запуске помогает ключ `gcc -fsanitize=undefined`: программа печатает сообщение вида `signed integer overflow` или `left shift of 1 by 31 places cannot be represented in type 'int'` в момент, когда это происходит.
:::

### Отношения, сравнения и логические операции {#sec:lec04:logical}

Операции отношения `>`, `>=`, `<`, `<=` и сравнения `==`, `!=` дают `1`, если отношение выполнено, и `0`, если нет; тип результата — `int`. Логические операции `!` (отрицание), `&&` (конъюнкция), `||` (дизъюнкция) считают ложью `0`, а истиной любое ненулевое значение, и тоже дают `0` или `1` типа `int`. Например, `!5` равно `0`, `!!5` равно `1`, `0 || -2` равно `1`. Это прямое следствие того, что исходно отдельного логического типа в C не было (тип `_Bool` появился только в C99, определение [-@def:lec03:bool]): условие — просто целое число, как и в регистрах процессора. Из всех целых ложь — только `0`; операции, которые сами вырабатывают логическое значение, дают `0` или `1`, а принимают как истину любое ненулевое.

Отсюда две устойчивые записи, которые часто встречаются в системном коде. `!x` равно `1` ровно тогда, когда `x` равно `0`, поэтому `if (!x)` пишут вместо `if (x == 0)`. `!!x` оставляет `0` нулем, а любое ненулевое значение превращает в `1`: так из «какой-то истины» получают ровно `1`, например `!!5` равно `1`.

::: {.remark #rem:lec04:chained-compare tag="частое заблуждение"}
*«`a > b > c` проверяет, что `b` лежит между `a` и `c`».* Так это работает в Python, но не в C: операции выполняются слева направо, `a > b > c` значит `(a > b) > c`, то есть `0` или `1` сравнивается с `c`. При `a = 3`, `b = 2`, `c = 1` математически $3 > 2 > 1$ верно, а выражение равно `(1) > 1`, то есть `0`. Правильно `a > b && b > c`. `gcc -Wall` предупреждает о такой записи.
:::

::: {.definition #def:lec04:short-circuit title="ленивое вычисление"}
Операции `&&` и `||` вычисляют операнды слева направо и *лениво*: если результат ясен по левому операнду, правый не вычисляется. У `a && b` правый операнд не вычисляется, если `a` равно `0`; у `a || b` — если `a` не равно `0`.
:::

Это гарантия стандарта, а не выбор компилятора, и на ней держится множество программ на C. Правый операнд часто имеет смысл, только если левый истинен. Условие `a != 0 && b / a > 5` безопасно при `a = 0`: до деления на ноль дело не доходит. Записанное в обратном порядке, `b / a > 5 && a != 0`, при `a = 0` уже содержит неопределенное поведение. В длинной цепочке `p1 && p2 && p3 && …` каждую следующую проверку можно писать в расчете на то, что все предыдущие уже выполнены и истинны: сначала убедиться, что делитель не ноль, потом делить; позже так же будут проверять, что индекс не выходит за массив, прежде чем обратиться к элементу. С остальными операциями такой гарантии нет: в `a + 5 + b` компилятор вправе вычислить операнды в любом порядке (замечание [-@rem:lec04:unspecified-order]).

::: {.example #ex:lec04:short-circuit-side}
Если в правом операнде есть побочный эффект, ленивое вычисление решает, произойдет ли он.

```c
int i = 0, j = 0;
int r = (i++ > 0) && (j++ > 0);   /* r = 0, i = 1, j = 0 */
r = i++ || j++;                    /* r = 1, i = 2, j = 0 */
```

В первой строке `i++ > 0` сравнивает старое значение `i`, то есть `0`, и дает `0`; правый операнд не вычисляется, `j` не меняется. Во второй строке `i++` дает `1` (истина), и `j++` снова пропускается.
:::

::: {.definition #def:lec04:conditional title="условная операция"}
*Условная операция* `c ? x : y` — единственная трехместная операция C. Сначала вычисляется условие `c`. Если оно не равно нулю, вычисляется `x`, и это значение всего выражения; иначе вычисляется `y`. Невыбранная ветка не вычисляется вовсе, после условия стоит точка следования. Если `x` и `y` разных арифметических типов, они приводятся к общему типу по обычным арифметическим преобразованиям.
:::

Например, `x < 0 ? -x : x` — модуль, `a > b ? a : b` — максимум. Приоритет у `?:` ниже, чем у `||`, но выше, чем у присваивания, поэтому `m = a > b ? a : b` пишется без скобок, а в `(a > b ? a : b) + 1` скобки нужны. Ассоциативность правая: `x < 0 ? -1 : x > 0 ? 1 : 0` читается как `x < 0 ? -1 : (x > 0 ? 1 : 0)` и дает знак числа.

::: {.remark #rem:lec04:conditional-type tag="подводный камень"}
Тип условного выражения не зависит от того, какая ветка выбрана. В `n > 0 ? -1 : 0u` ветки имеют типы `int` и `unsigned int`, общий тип по правилу 4 обычных арифметических преобразований (раздел [-@sec:lec04:conversions]) — `unsigned int`. При `n > 0` значение равно не $-1$, а $4294967295$, и `(n > 0 ? -1 : 0u) < 0` ложно при любом `n`. `gcc -Wextra` предупреждает: `operand of '?:' changes signedness`.
:::

## Присваивания и побочные эффекты

### Присваивание как выражение

Смысл программы в том, чтобы изменить память: машина Тьюринга, которая ездит по ленте и ничего не пишет, ничего и не вычисляет. Пока у нас из способов назвать ячейку памяти есть только имя переменной (позже добавятся элемент массива, поле структуры и указатель), и единственный способ изменить память — присвоить переменной значение. У присваивания два операнда: куда писать и что писать. Пишут их в порядке чтения: куда — слева от `=`, что — справа. Отсюда названия, которые перешли и в стандарты других языков.

::: {.definition #def:lec04:lvalue title="lvalue и rvalue"}
*lvalue* — выражение, которое указывает на объект в памяти: имя переменной (позже — элемент массива, `*p`). *rvalue* — выражение, которое только дает значение: `a + 1`, `5`, `a++`. Слева от `=` может стоять только изменяемое lvalue.
:::

Справа может стоять любое выражение, у которого есть значение. Слева — только выражение, которое указывает, куда писать. Например, `5 = 7`, `a + 1 = 5` и `5 = a` — ошибки компиляции: ни `5`, ни `a + 1` не называют ячейку памяти.

В Pascal присваивание — оператор (statement, определение [-@def:lec04:expression]): законченная команда, у которой нет значения. В C присваивание `lvalue = rvalue` — операция, и `a = 5` — выражение со значением. Его *основной эффект* — значение: значение левой части после присваивания, тип — тип левой части. Запись в память считается *побочным эффектом* вычисления выражения, хотя ради неё присваивание и пишут. Побочным эффектом считается и вызов функции: по тексту вызова компилятор не может понять, меняет ли функция что-нибудь (её текст может быть в другом файле или слишком сложным), поэтому любой вызов на всякий случай считается изменяющим память. Функцию без побочных эффектов, вроде $\sin x$, которая только вычисляет значение, можно было бы вызвать один раз для одного аргумента и запомнить результат, но пометить функцию такой позволяют только расширения компиляторов, в стандарт C это не входит.

Раз у присваивания есть значение, присваивания можно сцеплять. Присваивание выполняется справа налево (ассоциативность правая), поэтому `a = b = c = d = 0` означает `a = (b = (c = (d = 0)))`. Сначала `d = 0`: значение выражения $0$, побочный эффект — запись $0$ в `d`. Это значение становится правой частью `c = …`, и так ноль проходит по всей цепочке, обнуляя все четыре переменные. Если бы присваивание было оператором, как в Pascal, цепочку написать было бы нельзя: у `d = 0` не было бы значения.

::: {.remark #rem:lec04:assign-in-condition tag="подводный камень"}
Раз присваивание — выражение со значением, `x = 0` можно написать там, где ждут сравнение `x == 0`. Условие `if (x = 0)` (об операторе `if` — на следующей лекции) присваивает `x` ноль и проверяет результат, то есть всегда ложно, а `x` испорчен. Компилятор такую запись принимает; `gcc -Wall` выдает предупреждение «suggest parentheses around assignment used as truth value».
:::

### Составное присваивание, инкремент и декремент, запятая {#sec:lec04:compound}

*Укороченное (составное) присваивание* `lvalue op= rvalue`, где `op` — двухместная арифметическая или поразрядная операция (`+=`, `-=`, `*=`, `/=`, `%=`, `<<=`, `>>=`, `&=`, `^=`, `|=`), означает `lvalue = lvalue op (rvalue)`, только `lvalue` вычисляется один раз: вместо `a = a + 7` пишут `a += 7`. Скобки вокруг правой части существенны: после `int n = 7; n *= 2 + 3;` значение `n` равно `35` (то есть `7 * 5`), а не `17`.

Такая запись пришла из ассемблера машин, на которых создавался C. Команда процессора `R1 = R2 + R3` хранит в себе код операции и номера трех регистров. Память тогда измерялась килобайтами, и команды делали короче: двухадресная команда `add R1, R2` означает `R1 = R1 + R2`. Выразить так можно всё то же самое, а программа заметно короче. Укороченное присваивание — та же идея в языке.

::: {.definition #def:lec04:incdec title="инкремент и декремент"}
`++x` и `x++` увеличивают `x` на единицу, `--x` и `x--` уменьшают. Значение *префиксной* формы `++x` — новое значение `x`, значение *постфиксной* `x++` — старое.
:::

```c
int i = 5;
int j = i++;   /* j = 5, i = 6 */
int k = ++i;   /* k = 7, i = 7 */
```

Побочный эффект у обеих форм одинаковый, различается только значение. У полной записи `a = a + 1` вопроса нет: значение присваивания — новое значение. У короткой записи можно было бы выбрать любое, и оба полезны: новое нужно чаще, а старое избавляет от отдельной переменной, когда нужно сначала взять значение, а потом увеличить. C не стал выбирать и дал обе формы. Если значение выражения не используется (`i++;` отдельным оператором), формы равносильны.

*Операция запятая* `e1, e2` вычисляет `e1`, отбрасывает его значение, затем вычисляет `e2`; значение и тип всего выражения — те же, что у `e2`. Например, `a = (b = 5, b + 2)` присваивает `b = 5`, затем `a = 7`. Скобки нужны: у запятой самый низкий приоритет, и `a = b = 5, b + 2` означало бы `(a = b = 5), b + 2`. Запятые между аргументами функции и в объявлении `int a, b;` — не операция, а разделители.

### Точки следования

Процессор работает только со значениями в своих регистрах (рис. [-@fig:lec03:c-machine]). Для `a = b + c` он загружает `b` и `c` из памяти в регистры, складывает их и записывает результат в `a`. Длинное выражение процессор за один раз не вычислит: оно разбивается на шаги, промежуточные результаты живут во временных регистрах, которых в программе не видно, а запись в память происходит в какой-то момент позже. Если одна часть выражения меняет переменную, а другая её читает, результат зависит от того, что произошло раньше. Кроме того, компилятор вправе переставлять вычисления внутри выражения в поисках более быстрого порядка. Чтобы программист мог на что-то опираться, стандарт фиксирует моменты, к которым всё готово.

::: {.definition #def:lec04:sequence-point title="точка следования"}
*Точка следования* (sequence point) — момент при выполнении программы, в который все побочные эффекты предыдущих вычислений закончены, а побочные эффекты последующих еще не начаты. Точки следования есть:

- после вычисления первого операнда `&&`, `||` и запятой и после условия в `?:`;
- в конце полного выражения (оператор-выражение, инициализатор, условие, выражение в `return`);
- после вычисления всех аргументов функции, перед её вызовом.

*Правило:* между двумя соседними точками следования значение переменной может изменяться не более одного раза, а старое значение можно читать только для вычисления нового. Нарушение — неопределенное поведение.
:::

Точки следования похожи на знаки препинания в тексте: точка с запятой в конце оператора — как точка в конце предложения, после неё все записи выполнены. Внутри выражения точки следования стоят только там, где порядок вычисления и так задан: после левого операнда `&&` и `||` (ленивое вычисление требует сначала вычислить его), после левого операнда запятой и после условия `?:`. Поэтому `(b = 5) && a + b > 7` определено: к правому операнду `b` уже равно $5$. А в `(b = 5) + b` точки следования между записью и чтением `b` нет, и это неопределенное поведение: `b` меняется и читается не ради вычисления нового значения.

::: {.example #ex:lec04:unsequenced}
`(a = 2) + (a = 3)` и `i++ + ++i` — неопределенное поведение: в обоих `a` и `i` меняются дважды без точки следования между изменениями. Это не «одно из двух значений, смотря по порядку»: стандарт о результате ничего не говорит, и компиляторы действительно расходятся. При `q = 5` выражение `q * ++q` у GCC 13 равно $36$, у Clang 18 — $30$. `gcc -Wall` в таких местах предупреждает: «operation on 'i' may be undefined».

`i = i++` — тоже неопределенное поведение: `i` меняется и присваиванием, и инкрементом. А `i = i + 1` в порядке: `i` меняется один раз, и старое значение читается ради нового.

`i++ && i` и `(i++, i * 10)` определены: после левого операнда `&&` и запятой стоит точка следования, к правому операнду `i` уже увеличено. При `i = 1` первое выражение равно `1`, второе — `20`.
:::

::: {.remark #rem:lec04:unspecified-order tag="подводный камень"}
Кроме `&&`, `||`, `,` (и условной операции), порядок вычисления операндов в C *не уточняется*, как и порядок вычисления аргументов функции: в `f() + g()` функции вызываются в любом порядке, но вызваны будут обе. Хуже, когда в аргументах одна и та же переменная читается и меняется: `printf("%d %d\n", i, i++)` — уже неопределенное поведение, потому что между аргументами точек следования нет.
:::

::: {.remark #rem:lec04:sequenced-before}
В стандартах C11 и новее вместо точек следования говорят об отношении «упорядочено до» (sequenced before): точка следования задает частичный порядок вычислений. Вычисления, не упорядоченные между собой (unsequenced), могут выполняться в любом порядке и даже перекрываться; изменение одного объекта двумя неупорядоченными побочными эффектами — неопределенное поведение. Для выражений этой лекции обе формулировки дают одно и то же.
:::


## Поразрядные операции

Поразрядные (побитовые) операции работают с целым как с набором бит: `&` (И), `|` (включающее ИЛИ), `^` (исключающее ИЛИ), `~` (инверсия, дополнение до единицы), `<<` и `>>` (сдвиги). Первые три применяются к каждой паре соответствующих бит. Для `a = 12` ($1100_2$) и `b = 10` ($1010_2$):

| Выражение | Биты | Значение |
| --- | --- | --- |
| `a & b` | $1000_2$ | $8$ |
| `a | b` | $1110_2$ | $14$ |
| `a ^ b` | $0110_2$ | $6$ |
| `~a & 0xF` | $0011_2$ | $3$ |

(`~a` инвертирует все 32 бита, поэтому для наглядности оставлены младшие четыре.)

::: {.remark #rem:lec04:logical-vs-bitwise tag="подводный камень"}
`&&` и `&` — разные операции. `2 && 1` равно `1` (оба истинны), а `2 & 1` равно `0` (у $10_2$ и $01_2$ нет общих единиц). Кроме того, `&` вычисляет оба операнда всегда, без ленивости.
:::

Сдвиг `x << k` сдвигает биты на $k$ позиций влево, освобожденные младшие биты заполняются нулями, вышедшие за старший край пропадают. `x >> k` сдвигает вправо; что попадает в освободившиеся старшие биты, зависит от типа (рис. [-@fig:lec04:shifts]).

::: {.definition #def:lec04:shifts title="сдвиги"}
В `E1 << E2` и `E1 >> E2` к каждому операнду применяется целочисленное продвижение (раздел [-@sec:lec04:conversions]); тип результата — тип продвинутого `E1`. Если `E2` отрицательно или не меньше числа бит этого типа, поведение не определено. Далее:

- `E1 << E2` для беззнакового `E1` равно $E1 \cdot 2^{E2}$ по модулю $2^N$; для знакового — $E1 \cdot 2^{E2}$, если `E1` неотрицательно и результат помещается в тип, иначе поведение не определено;
- `E1 >> E2` для беззнакового или неотрицательного знакового `E1` равно целой части $E1 / 2^{E2}$ (освобожденные биты — нули, *логический сдвиг*); для отрицательного знакового результат определяется реализацией: заполнение знаковым битом (*арифметический сдвиг*) или нулями. GCC делает арифметический сдвиг: `-76 >> 2` равно `-19`.
:::

::: {.remark #rem:lec04:one-shift-31 tag="подводный камень"}
`1 << 31` при 32-битном `int` — неопределенное поведение: $2^{31}$ не помещается в `int`. Маску старшего бита пишут беззнаковой: `1u << 31` равно $2147483648$. Сдвиг на ширину типа, `x << 32` для 32-битного `x`, тоже не определен: он не обязан давать $0$, и результат на разных машинах разный. По той же причине `1 << 40` — неопределенное поведение: константа `1` имеет тип `int`. Широким должен быть левый операнд: `1ULL << 40` равно $2^{40} = 1099511627776$.
:::

Поразрядными операциями удобно работать с отдельными битами. *Маска* `1u << k` — число, у которого единица только в бите $k$ (биты нумеруются с $0$ от младшего). Тогда для беззнакового `x`:

| Действие с битом $k$ | Выражение | Почему |
| --- | --- | --- |
| проверить | `(x >> k) & 1u` | бит $k$ сдвигается в младший разряд |
| установить в 1 | `x | (1u << k)` | `|` с единицей дает 1, с нулем не меняет бит |
| сбросить в 0 | `x & ~(1u << k)` | `~` маски — нуль только в бите $k$ |
| инвертировать | `x ^ (1u << k)` | `^` с единицей меняет бит, с нулем — нет |

Еще несколько приемов (их много в книге Г. Уоррена «Алгоритмические трюки для программистов», Hacker's Delight). Для `x = 0xB4` ($10110100_2 = 180$):

- `x & 1` — младший бит, то есть нечетность: `0`;
- `x & (x - 1)` сбрасывает самую младшую единицу: `x - 1` равно $10110011_2$, результат $10110000_2 = 176$;
- `x | (x + 1)` устанавливает самый младший нуль: $10110101_2 = 181$;
- `(1u << k) - 1` — маска из $k$ младших единиц (при $0 \le k < 32$), и `x & ((1u << 4) - 1)` оставляет четыре младших бита: $0100_2 = 4$;
- `~x + 1` равно `-x` в дополнительном коде: для `int s = -76` выражение `~s + 1` равно `76`.

Прием `x & (x - 1)` понадобится в практике: у степени двойки ровно одна единица, и после её сброса остается ноль. В C23 для таких задач появился заголовок `stdbit.h` с функциями `stdc_count_ones` (число единиц), `stdc_bit_floor` (наибольшая степень двойки, не превосходящая `x`) и другими.

::: {.example #ex:lec04:xor-swap title="обмен без третьей переменной"}
Три присваивания `x ^= y, y ^= x, x ^= y` меняют значения `x` и `y` местами (`x ^= y` значит `x = x ^ y`). Пусть сначала `x` $= a$, `y` $= b$. После первого `x` $= a \oplus b$; после второго `y` $= b \oplus a \oplus b = a$; после третьего `x` $= a \oplus b \oplus a = b$. Здесь используется, что $\oplus$ коммутативна, ассоциативна и $t \oplus t = 0$. Для `x = 5`, `y = 9` получаем `x = 9`, `y = 5`.
:::

::: {.remark #rem:lec04:xor-swap-same tag="корнер-кейс"}
Если `x` и `y` — один и тот же объект в памяти (так бывает при работе через указатели, о них позже), первое же `x ^= x` дает $0$, и значение теряется. Обычный обмен через временную переменную этого недостатка не имеет и компилируется не хуже.
:::

## Приоритеты

Порядок выполнения операций без скобок задается приоритетами. Столбец «Порядок» — ассоциативность: как расставить скобки в цепочке операций одного приоритета. `a - b - c` значит `(a - b) - c`, а `a = b = c` значит `a = (b = c)`. Сверху вниз — от высшего приоритета к низшему:

| Приоритет | Операции | Порядок |
| --- | --- | --- |
| 1 | `x++`, `x--` (постфиксные) | слева направо |
| 2 | `++x`, `--x`, одноместные `+` `-`, `!`, `~`, `(тип)`, `sizeof` | справа налево |
| 3 | `*`, `/`, `%` | слева направо |
| 4 | `+`, `-` | слева направо |
| 5 | `<<`, `>>` | слева направо |
| 6 | `<`, `<=`, `>`, `>=` | слева направо |
| 7 | `==`, `!=` | слева направо |
| 8 | `&` | слева направо |
| 9 | `^` | слева направо |
| 10 | `|` | слева направо |
| 11 | `&&` | слева направо |
| 12 | `||` | слева направо |
| 13 | `?:` | справа налево |
| 14 | `=`, `+=`, `-=`, `*=`, `/=`, `%=`, `<<=`, `>>=`, `&=`, `^=`, `|=` | справа налево |
| 15 | `,` | слева направо |

::: {.remark #rem:lec04:bit-precedence tag="подводный камень"}
Поразрядные `&`, `^`, `|` стоят *ниже* сравнений. Поэтому `x & 1 == 0` читается как `x & (1 == 0)`, то есть `x & 0`, и всегда равно `0`. Проверка четности пишется со скобками: `(x & 1) == 0`. Так же `1 << n - 1` — это `1 << (n - 1)`, потому что `-` старше сдвига. При сомнении ставят скобки; `gcc -Wall` предупреждает о самых частых случаях.
:::

## Приведение типов {#sec:lec04:conversions}

### Явное приведение

Пусть нужно среднее двух целых, `a = 7` и `b = 2`.

```c
int a = 7, b = 2;
double d1 = (a + b) / 2;            /* 4.0 */
double d2 = (double)(a + b) / 2;    /* 4.5 */
```

В `d1` деление целое: `9 / 2` равно `4`, и уже готовое `4` превращается в `4.0` при присваивании. Тип результата определяется типами операндов, а не тем, куда результат записывают. Чтобы деление стало вещественным, хотя бы один операнд должен быть вещественным.

::: {.definition #def:lec04:cast title="явное приведение типа"}
Выражение `(тип) выражение` (*приведение*, cast) преобразует значение выражения к указанному типу. Приведение — одноместная операция с приоритетом одноместных операций: оно связывает сильнее, чем `*`, `/`, `+`.
:::

::: {.remark #rem:lec04:cast-placement tag="подводный камень"}
Место приведения решает всё. `(double)(a + b) / 2` и `((double) a + b) / 2` дают `4.5`: в первом приводится сумма, во втором — `a`, и дальше сложение и деление идут в `double`. А `(double)((a + b) / 2)` дает `4.0`: приводится результат уже выполненного целого деления. Можно обойтись без приведения: `(a + b) / 2.0`, потому что `2.0` — константа типа `double`.
:::

### Преобразование при присваивании

При присваивании `a = b` значение `b` преобразуется к типу `a`. Если оно помещается в тип `a`, оно не меняется. Если нет:

- целое → беззнаковое целое: значение берется по модулю $2^N$, где $N$ — ширина целевого типа; в дополнительном коде это значит «отсекаются старшие биты», а у знакового источника знаковый бит «становится» значащим. Так, `(unsigned char) 300` равно `44` ($300 - 256$), а `signed char c = -1;` дает `(unsigned char) c`, равное `255`;
- целое → знаковое целое, которое не вмещает значение: результат определяется реализацией. GCC тоже берет остаток по модулю $2^N$ и трактует его в дополнительном коде: `signed char s = 300;` дает `44`, `signed char s = 200;` дает `-56`;
- вещественное → целое: дробная часть отбрасывается (округление к нулю): `(int) 3.7` равно `3`, `(int) -3.7` равно `-3`. Если целая часть не помещается в целый тип, поведение не определено;
- `double` → `float`: если значение помещается в диапазон `float`, оно округляется до ближайшего представимого (или соседнего, по выбору реализации); выход за диапазон — неопределенное поведение (в IEEE 754 — бесконечность).

### Целочисленное продвижение

Процессор складывает регистры целиком, а не отдельные байты. Поэтому в C короткие целые типы в выражениях сначала расширяются.

::: {.definition #def:lec04:promotion title="целочисленное продвижение"}
*Целочисленное продвижение* (integer promotion): значение типа с меньшим рангом, чем `int` (`_Bool`, `char`, `signed char`, `unsigned char`, `short`, `unsigned short`), перед арифметической, поразрядной или одноместной операцией преобразуется к `int`, если `int` может представить все значения исходного типа, и к `unsigned int` иначе.
:::

*Ранг* (integer conversion rank) — заданный стандартом порядок целых типов: `_Bool` < `char` < `short` < `int` < `long` < `long long`; у знакового и беззнакового варианта одного типа ранг одинаковый (даже если два типа имеют одинаковую ширину, например 8-байтовые `long` и `long long`, их ранги различны).

::: {.example #ex:lec04:promotion}
```c
unsigned char x = 200, y = 100;
unsigned char z = x + y;
printf("%d %d\n", x + y, z);   /* 300 44 */
printf("%zu\n", sizeof(x + y)); /* 4 */
```

`x + y` вычисляется в `int`: оба операнда продвигаются, сумма $300$ помещается. Переполнения `unsigned char` здесь нет. $44$ появляется только при записи в `z`, по правилу «по модулю $2^8$». И `sizeof(x + y)` равен `sizeof(int)`, а не `1`.
:::

::: {.example #ex:lec04:short-sum title="сумма двух short (при 4-байтовом int)"}
```c
short a = 31500, b = 31500;
short s = a + b;
printf("%d %hd\n", a + b, s);   /* 63000 -2536 */
```

При 4-байтовом `int` переполнения при сложении нет: `a` и `b` продвигаются в `int`, и `a + b` равно $63000$. Значение теряется при записи в `short` (16 бит, от $-32768$ до $32767$): $63000$ туда не помещается, результат определяется реализацией (преобразование при присваивании, выше), и GCC берет его по модулю $2^{16}$: $63000 - 65536 = -2536$. Поэтому проверка делается до записи: сумму считают в `int` и сравнивают с `SHRT_MIN` и `SHRT_MAX` из `limits.h`. (На машине с 2-байтовым `int` сложение `a + b` уже переполняет `int` и дает неопределенное поведение.)
:::

::: {.remark #rem:lec04:promotion-short tag="корнер-кейс"}
Продвижение идет в `unsigned int`, только если `int` не вмещает всех значений типа. Обычно (`short` 2 байта, `int` 4) `unsigned short` продвигается в `int`. Но стандарт допускает `short` и `int` по 4 байта; тогда `unsigned short` не помещается в `int` и продвигается в `unsigned int`. Результат одного и того же выражения зависит от размеров типов на машине.
:::

::: {.remark #rem:lec04:promotion-not tag="подводный камень"}
Продвижение действует и на одноместные `~` и `-`. Если `unsigned char c = 0;`, то `~c` — это `~0` в `int`, то есть `-1`, а не `255`, и сравнение `~c == 0xFF` ложно. Так же `(unsigned char) 0xF0 << 4` равно `3840` типа `int`: старшие биты не пропадают, пока результат не записали обратно в `unsigned char`.
:::

### Обычные арифметические преобразования

Двухместная операция над операндами разных типов сначала приводит их к общему типу. В нём выполняется операция, он же — тип результата (у сравнений результат `int`, но сравниваются значения общего типа).

::: {.definition #def:lec04:usual-conversions title="обычные арифметические преобразования"}
Общий тип операндов двухместной операции находится так (правила применяются по порядку, срабатывает первое подходящее).

1. Если один операнд `long double`, второй преобразуется к `long double`; иначе если один `double`, второй — к `double`; иначе если один `float`, второй — к `float`.
2. Иначе к обоим операндам применяется целочисленное продвижение. Если после него типы совпали, преобразование закончено.
3. Если оба знаковые или оба беззнаковые, операнд меньшего ранга преобразуется к типу большего ранга.
4. Если ранг беззнакового операнда не меньше ранга знакового, знаковый преобразуется к беззнаковому типу.
5. Если знаковый тип может представить все значения беззнакового, беззнаковый операнд преобразуется к знаковому типу.
6. Иначе оба преобразуются к беззнаковому типу, соответствующему знаковому операнду.
:::

Правило 4 — источник самых неожиданных результатов: при одинаковой ширине знаковое уступает беззнаковому, и отрицательное число становится огромным положительным ($-1 \mapsto 2^{32} - 1$).

::: {.example #ex:lec04:usual-conversions title="общий тип при int 4, long 8 байт"}
| Выражение | Правило | Общий тип |
| --- | --- | --- |
| `int + double` | 1 | `double` |
| `float + long long` | 1 | `float` |
| `unsigned short + char` | 2 | `int` |
| `int + long` | 3 | `long` |
| `unsigned long long + unsigned` | 3 | `unsigned long long` |
| `int + unsigned long` | 4 | `unsigned long` |
| `int / unsigned int` | 4 | `unsigned int` |
| `unsigned int + long` | 5 | `long` |
| `unsigned long + long long` | 6 | `unsigned long long` |

Во второй строке целое `long long` преобразуется во `float`: вещественный тип старше любого целого, даже более длинного. В третьей оба операнда продвигаются в `int`. В строке с правилом 5 `long` вмещает все значения `unsigned int`. В последней `long long` старше `unsigned long` по рангу, но при одинаковой ширине 8 байтов не вмещает $2^{64} - 1$, поэтому общий тип — беззнаковая версия знакового. Если же `long` занимает 4 байта, как `int` (так в 64-битной Windows), то правило 6 срабатывает уже в `unsigned int + long`: `long` не вмещает $4294967295$, общий тип — `unsigned long`.

По правилу 1 `float + float` остается `float`, автоматического перехода к `double` нет. А точность `float` невелика, около семи десятичных цифр: `100000000.0f + 1.0f`, вычисленное во `float`, равно `100000000.0f`, единица теряется. `100000000.0f + (double) 1.0f` вычисляется в `double` и дает $100000001$.
:::

::: {.example #ex:lec04:signed-unsigned title="«неверные значения»"}
```c
printf("%d\n", -1 < 0u);       /* 0 */
printf("%u\n", -6 / 2u);       /* 2147483645 */
long l = -1;
printf("%d\n", l < 1u);        /* 1 */
```

В `-1 < 0u` по правилу 4 `-1` превращается в $2^{32} - 1 = 4294967295$, и это не меньше $0$. В `-6 / 2u` делится $2^{32} - 6 = 4294967290$ на $2$. В `l < 1u` при 8-байтовом `long` срабатывает правило 5: `1u` становится `long`, сравниваются $-1$ и $1$ как обычно.
:::

::: {.remark #rem:lec04:sizeof-compare tag="подводный камень"}
Результат `sizeof` беззнаковый (см. ниже), поэтому `sizeof(int) > -1` ложно: `-1` преобразуется к беззнаковому типу и становится наибольшим его значением. Та же ловушка — в сравнении счетчика `int i` с беззнаковой длиной: при `i < 0` условие `i < len` окажется ложным. `gcc -Wall -Wextra` предупреждает о сравнении знакового с беззнаковым (`-Wsign-compare`); это предупреждение стоит читать. Сравнение беззнакового с нулем тоже обманчиво: `u >= 0` истинно при любом `u`, поэтому цикл, который уменьшает беззнаковый счетчик «до нуля включительно», не останавливается (что с таким циклом делает оптимизирующий компилятор — в замечании [-@rem:lec03:infinite-loop]). Об этом предупреждает `-Wextra` (`-Wtype-limits`).
:::

## Операция `sizeof`

::: {.definition #def:lec04:sizeof title="sizeof"}
`sizeof(тип)` и `sizeof выражение` дают размер типа (типа выражения) в байтах. Это операция, а не функция: скобки нужны только вокруг имени типа. Результат имеет беззнаковый целый тип `size_t` (объявлен в `stddef.h`, `stdio.h` и других заголовках) и печатается спецификатором `%zu`. `sizeof(char)` равно `1` по определению.
:::

Тип выражения находится по правилам выше, поэтому `sizeof` удобно использовать, чтобы их проверять: для `char c` `sizeof c` равно `1`, `sizeof(c + c)` равно `4` (продвижение в `int`), `sizeof(c + 1L)` равно `8` (общий тип `long`).

::: {.remark #rem:lec04:sizeof-unevaluated tag="корнер-кейс"}
Операнд `sizeof` не вычисляется: компилятору нужен только его тип, а тип известен до запуска программы. После `int i = 5; size_t s = sizeof(i++);` значение `i` по-прежнему `5`, а `s` равно `4`. (Исключение — массивы переменной длины, о них позже.)
:::

## Ввод и вывод целых {#sec:lec04:io}

### Вывод: `printf`

Примеры выше печатали значения разных типов спецификаторами `%d`, `%u`, `%zu`. Сведем их вместе. Спецификатор должен соответствовать типу аргумента: `printf` не знает, что ей передали, и читает аргумент так, как велит формат. Несоответствие (например, `%d` для `unsigned long` или для `double`) — неопределенное поведение. `gcc -Wall` такие места находит: `format '%d' expects argument of type 'int', but argument 2 has type 'double'`.

| Спецификатор | Тип аргумента | Как печатает |
| --- | --- | --- |
| `%d`, `%ld`, `%lld` | `int`, `long`, `long long` | десятичное со знаком |
| `%u`, `%lu`, `%llu` | `unsigned`, `unsigned long`, `unsigned long long` | десятичное без знака |
| `%x`, `%o` | `unsigned` (с `l`, `ll` — длиннее) | шестнадцатеричное, восьмеричное |
| `%c` | `int` (код символа) | символ |
| `%zu` | `size_t` (результат `sizeof`) | десятичное без знака |
| `%f` | `double` | десятичная дробь, $6$ знаков после точки |
| `%%` | — | знак `%` |

Полный вид спецификатора — `%[флаги][ширина][.точность][длина]буква`. Длина — это `h`, `l`, `ll`, `z` перед буквой (`h` означает `short`: `%hd`, `%hu`). Ширина — наименьшее число позиций: `%5d` дополняет число пробелами слева до пяти знаков. Флаг `-` прижимает значение к левому краю, `0` дополняет нулями, `+` печатает знак и у положительных, `#` добавляет к `%x` префикс `0x`. Точность у `%f` — число знаков после точки.

```c
printf("[%5d] [%-5d] [%05d] [%+d]\n", 42, 42, 42, 42);
printf("[%x] [%X] [%#x] [%o]\n", 255u, 255u, 255u, 8u);
printf("%.2f\n", 3.14159);
```

Эти вызовы печатают:

```
[   42] [42   ] [00042] [+42]
[ff] [FF] [0xff] [10]
3.14
```

Сама `printf` тоже возвращает значение: число напечатанных символов (при ошибке вывода — отрицательное число). Обычно его не используют.

::: {.remark #rem:lec04:printf-promotion tag="корнер-кейс"}
Аргументы на месте многоточия в объявлении `int printf(const char *format, ...)` перед вызовом продвигаются: `char` и `short` становятся `int` (раздел [-@sec:lec04:conversions]), `float` становится `double`. Поэтому `%d` годится и для `char`, и для `short`, `%c` получает код символа типа `int`, а `%f` печатает и `float`, и `double`. У `scanf` такой поблажки нет (ниже).
:::

### Ввод: `scanf`

Функция `scanf` из `stdio.h` читает стандартный поток ввода по форматной строке с теми же спецификаторами. `printf` значения нужно только прочитать, а `scanf` должна их записать, поэтому получает не переменные, а их адреса: `&a` — адрес переменной `a` (подробно — когда дойдем до указателей). Спецификатор `%d` пропускает пробелы и переводы строк перед числом и читает знак и цифры, пока они идут.

`scanf` возвращает, сколько значений удалось прочитать и записать. Если ввод кончился раньше, чем прочитано первое значение, она возвращает константу `EOF` (отрицательную, обычно $-1$). Переменные, которые прочитать не удалось, не меняются. Ввод может прийти любой, и от программы ждут не только правильного ответа на правильный ввод.

::: {.definition #def:lec04:robust title="корректная и удобная программа"}
Программа *корректна*, если на любой допустимый ввод выдает вывод, который требует задача. Корректная программа *удобна*, если на любой недопустимый ввод выдает понятное сообщение об ошибке.
:::

::: {.example #ex:lec04:scanf-check title="сумма двух чисел с проверкой ввода"}
```c
#include <stdio.h>

int main(void)
{
    int a = 0, b = 0;
    int got = scanf("%d%d", &a, &b);
    if (got != 2) {
        printf("ошибка: ожидались два целых числа (прочитано %d)\n", got);
        return 1;
    }
    printf("%d\n", a + b);
    return 0;
}
```

`if` выполняет блок в фигурных скобках, если условие не равно нулю (подробно — на следующей лекции). Что получается на разном вводе:

| Ввод | `got` | Вывод |
| --- | --- | --- |
| `12 7` | $2$ | `19` |
| `12`, перевод строки, `7` | $2$ | `19` |
| `12 abc` | $1$ | сообщение об ошибке, код завершения $1$ |
| `12.5 3` | $1$ | сообщение об ошибке: `%d` прочитал `12` и остановился на точке |
| пустой ввод | $-1$ (`EOF`) | сообщение об ошибке |

Без проверки на вводе `12 abc` программа молча напечатала бы `12`: `b` осталась бы нулем. А если бы `b` не была инициализирована, напечаталось бы непредсказуемое число.
:::

::: {.remark #rem:lec04:scanf-types tag="подводный камень"}
В `scanf` спецификатор должен совпадать с типом переменной точно: продвижения здесь нет, `scanf` записывает по адресу столько байтов, сколько велит формат. Для `short` нужен `%hd`, для `long` — `%ld`, для `double` — `%lf` (а в `printf` для `double` — `%f`). `scanf("%f", &d)` для `double d` — неопределенное поведение: `%f` ждет адрес `float` и запишет $4$ байта из $8$. `gcc -Wall` предупреждает и об этом: `format '%f' expects argument of type 'float *', but argument 2 has type 'double *'`.
:::

Выражения этой лекции понадобятся на следующей, где они станут условиями операторов `if`, `while` и `for`: в заголовке цикла `for` три выражения, и в каждом действуют те же правила побочных эффектов и точек следования.

# Практика

::: {.problem #prob:lec04:scope}
Что напечатает программа?

```c
#include <stdio.h>

int n = 10;

int f(void)
{
    static int calls;
    int n = 0;
    calls++;
    n++;
    return calls * 100 + n;
}

int main(void)
{
    printf("%d\n", f());
    printf("%d\n", f());
    n++;
    printf("%d %d\n", f(), n);
    return 0;
}
```
:::

::: solution
*Ключ:* для каждого имени отдельно решить, какая переменная за ним стоит (самая внутренняя видимая) и в какой она памяти.

Внутри `f` имя `n` означает локальную автоматическую переменную: при каждом вызове она заново равна $0$ и после `n++` равна $1$. Глобальную `n` функция не видит. `calls` — статическая: без инициализатора она обнулена до начала `main` и между вызовами сохраняет значение. Поэтому вызовы `f` возвращают $101$, $201$, $301$. `n++` в `main` относится к глобальной `n`, она становится $11$. Программа печатает:

```
101
201
301 11
```

Порядок вычисления аргументов `printf` в последней строке не уточняется, но здесь он не важен: `f` глобальную `n` не меняет.
:::

::: {.problem #prob:lec04:init}
Функция `h` вызывается дважды.

```c
int g;

void h(void)
{
    static int s;
    int a;
    int b = 5;
    /* место 1 */
    s = 7;
    a = 3;
}
```

Какие значения у `g`, `s`, `a`, `b` в месте 1 при первом вызове и при втором?
:::

::: solution
*Ключ:* начальное значение без инициализатора зависит от класса памяти, а не от того, где объявлена переменная.

- `g` — глобальная, статическая память, без инициализатора обнулена: $0$ при обоих вызовах (`h` её не меняет).
- `s` — статическая: при первом вызове $0$, при втором $7$, потому что значение, записанное в первом вызове, сохранилось.
- `a` — автоматическая без инициализатора: значение не определено при обоих вызовах. То, что в прошлый раз в неё записали $3$, ничего не значит: при выходе из `h` память `a` освобождена, при новом входе выделена заново. Читать `a` в месте 1 нельзя.
- `b` — автоматическая с инициализатором: $5$ при каждом вызове.
:::

::: {.problem #prob:lec04:literals}
Пусть `int` занимает 4 байта, `long` — 8. Найди значение (в десятичной записи) и тип каждой константы: `0x1F`, `017`, `'0'`, `0xFFFFFFFF`, `4294967295`, `10UL`.
:::

::: solution
*Ключ:* сначала система счисления по префиксу, затем тип — первый подходящий в списке для этой записи и суффикса.

- `0x1F` $= 16 + 15 = 31$, помещается в `int`;
- `017` $= 8 + 7 = 15$ (ведущий ноль — восьмеричная), `int`;
- `'0'` — код символа нуля в ASCII, $48$; символьная константа имеет тип `int`;
- `0xFFFFFFFF` $= 2^{32} - 1 = 4294967295$ не помещается в `int`; для шестнадцатеричной следующий в списке `unsigned int`, в него помещается;
- `4294967295` — то же значение, но десятичная константа без суффикса: в списке нет `unsigned int`, следующий после `int` — `long`;
- `10UL` — $10$, суффикс задает `unsigned long`.
:::

::: {.problem #prob:lec04:division}
Вычисли `-23 / 4`, `-23 % 4`, `23 / -4`, `23 % -4`. Запиши выражение, которое для любого `int a` и `b = 4` дает остаток из $\{0, 1, 2, 3\}$, и вычисли его при `a = -23`.
:::

::: solution
Частное округляется к нулю: $-23 / 4 = -5{,}75$, `-23 / 4` равно `-5`; остаток из тождества [-@eq:lec04:div-identity]: $-23 - (-5) \cdot 4 = -3$. Так же `23 / -4` равно `-5`, а `23 % -4` равно $23 - (-5) \cdot (-4) = 3$. Знак остатка — как у делимого.

*Ключ:* остаток `a % b` лежит в $(-b, b)$; прибавив `b`, получаем число из $(0, 2b)$, и еще один `% b` возвращает его в $[0, b)$. При `a = -23`: `(-23 % 4 + 4) % 4` равно `(-3 + 4) % 4`, то есть `1`. Проверка: $-23 = -6 \cdot 4 + 1$.

*Ответ:* `-5`, `-3`, `-5`, `3`; выражение `(a % 4 + 4) % 4`, при `a = -23` оно равно `1`.
:::

::: {.problem #prob:lec04:overflow}
`int` и `unsigned` 32-битные. Какие выражения содержат неопределенное поведение, а какие определены (и чему равны)?

- (а) `INT_MAX + 1`;
- (б) `UINT_MAX + 1`;
- (в) `INT_MAX + 1u`;
- (г) `-INT_MIN`;
- (д) `1 << 31`;
- (е) `1u << 31`;
- (ж) `INT_MIN / -1`.
:::

::: solution
*Ключ:* сначала найти тип, в котором выполняется операция (по обычным арифметическим преобразованиям), и только потом решать: беззнаковый тип — результат по модулю $2^{32}$, знаковый — проверить, помещается ли результат.

- (а) Оба операнда `int`, $2^{31}$ не помещается — неопределенное поведение.
- (б) `UINT_MAX` имеет тип `unsigned int`, `1` преобразуется к нему; $2^{32} \bmod 2^{32} = 0$ — определено.
- (в) `INT_MAX` по правилу 4 становится `unsigned int`; $2^{31} = 2147483648$ помещается — определено.
- (г) $-(-2^{31}) = 2^{31}$ не помещается в `int` — неопределенное поведение.
- (д) `1` типа `int`, $1 \cdot 2^{31}$ не помещается — неопределенное поведение.
- (е) Беззнаковый сдвиг: $2^{31} = 2147483648$ — определено.
- (ж) Частное $2^{31}$ не помещается — неопределенное поведение.

*Ответ:*

- неопределенное поведение — (а), (г), (д), (ж);
- (б) равно `0`;
- (в) и (е) равны `2147483648`.
:::

::: {.problem #prob:lec04:lazy}
После `int i = 0, j = 5;` выполняются `int r = i && j++;` и затем `int s = i++ || --j;`. Чему равны `r`, `s`, `i`, `j`?
:::

::: solution
*Ключ:* правый операнд `&&` вычисляется, только если левый не ноль; правый операнд `||` — только если левый ноль.

`r = i && j++`: `i` равно `0`, результат `0` ясен, `j++` не выполняется; `r = 0`, `j = 5`.

`s = i++ || --j`: `i++` дает старое значение `0` (ложь), `i` становится `1`. Результат еще не ясен, вычисляется `--j`: `j = 4`, значение `4` — истина; `s = 1`.

*Ответ:* `r = 0`, `s = 1`, `i = 1`, `j = 4`.
:::

::: {.problem #prob:lec04:conditions}
Запиши выражения на C, равные `1`, когда условие выполнено, и `0` иначе:

- (а) `x` лежит в $[-3, 10)$;
- (б) `x` лежит в $(-\infty, 2] \cup [7, +\infty)$;
- (в) `x` лежит в $(A, B] \cap [C, D)$.
:::

::: solution
*Ключ:* двойное неравенство в C записывают двумя сравнениями через `&&`, объединение промежутков — через `||`, пересечение — через `&&`.

- (а) `x >= -3 && x < 10`. Запись `-3 <= x < 10` скомпилируется, но сравнит с $10$ результат `-3 <= x`, то есть `0` или `1` (замечание [-@rem:lec04:chained-compare]).
- (б) `x <= 2 || x >= 7`. С `&&` получилось бы условие, которое не выполняется ни при каком `x`.
- (в) `x > A && x <= B && x >= C && x < D`.
:::

::: {.problem #prob:lec04:ternary}
Запиши через условную операцию `?:`:

- (а) модуль `x`;
- (б) максимум из `a`, `b`, `c`.
:::

::: solution
(а) `x < 0 ? -x : x`. При `x = INT_MIN` это неопределенное поведение: `-INT_MIN` в `int` не помещается (замечание [-@rem:lec03:min-value]).

(б) `a > b ? (a > c ? a : c) : (b > c ? b : c)`: сначала выбираем большее из `a` и `b`, затем сравниваем его с `c`. Внутренние скобки можно опустить — вокруг третьей части из-за правой ассоциативности `?:`, а вокруг средней потому, что знаки `?` и `:` в грамматике C сами ограничивают произвольное выражение, как скобки, — но со скобками выражение легче прочитать.
:::

::: {.problem #prob:lec04:increments}
Чему равны `a`, `b`, `c` после выполнения строк по порядку?

```c
int a = 4, b, c;
b = a++ + 3;
a *= b - 5;
b = --a * 2;
c = (a += 1, a / 2);
```
:::

::: solution
*Ключ:* у постфиксной формы значение — старое, у префиксной — новое; `a *= b - 5` значит `a = a * (b - 5)`.

1. `b = a++ + 3`: `a++` дает $4$, `b = 7`, `a = 5`.
2. `a *= b - 5`: `a = 5 * (7 - 5) = 10`.
3. `b = --a * 2`: `--a` дает $9$, `a = 9`, `b = 18`.
4. `c = (a += 1, a / 2)`: сначала `a = 10`, затем значение запятой — `a / 2`, то есть $5$.

*Ответ:* `a = 10`, `b = 18`, `c = 5`.
:::

::: {.problem #prob:lec04:sequence}
Какие операторы содержат неопределенное поведение?

- (а) `i = i + 1;`
- (б) `i = i++ + 1;`
- (в) `j = i++ && i;`
- (г) `j = i++ + i;`
- (д) `j = (i++, i);`
- (е) `printf("%d %d\n", i, ++i);`
- (ж) `x ^= y ^= x ^= y;`
- (з) `j = i++ ? i++ : ++i;`
:::

::: solution
*Ключ:* найти точки следования внутри выражения и проверить, меняется ли `i` дважды или читается ли не ради нового значения между двумя соседними точками.

- (а) `i` меняется один раз, старое значение читается ради нового — определено.
- (б) `i` меняется инкрементом и присваиванием без точки следования между ними — неопределенное поведение.
- (в) После левого операнда `&&` есть точка следования: правое `i` читается уже после инкремента — определено.
- (г) `i` меняется в `i++` и читается во втором слагаемом не ради нового значения, точки следования между ними нет — неопределенное поведение.
- (д) После левого операнда запятой — точка следования — определено.
- (е) Между аргументами функции точек следования нет: `i` читается во втором аргументе и меняется в третьем — неопределенное поведение.
- (ж) `^=` правоассоциативна: `x ^= (y ^= (x ^= y))`. `x` меняется и внутренним, и внешним `^=` без точки следования между ними — неопределенное поведение. Поэтому обмен через `^` пишут через запятую или тремя операторами, как в примере [-@ex:lec04:xor-swap].
- (з) После условия `?:` стоит точка следования, а из двух веток вычисляется одна, так что `i` между соседними точками меняется один раз — определено. При `i = 1` условие `i++` равно `1`, `i` становится $2$, затем ветка `i++` дает `j = 2`, `i = 3`.

*Ответ:* неопределенное поведение в (б), (г), (е), (ж).
:::

::: {.problem #prob:lec04:masks}
Для `unsigned x = 0xB4` и `k = 2` вычисли: `x` с установленным битом $k$, со сброшенным битом $k$, с инвертированным битом $k$ и значение бита $k$. Запиши выражения.
:::

::: solution
`0xB4` $= 10110100_2 = 180$; маска `1u << 2` $= 00000100_2 = 4$, бит $2$ в `x` равен $1$.

- установить: `x | (1u << k)` — бит уже $1$, получаем $180$;
- сбросить: `x & ~(1u << k)` — $10110000_2 = 176$;
- инвертировать: `x ^ (1u << k)` — бит был $1$, стал $0$: $176$;
- проверить: `(x >> k) & 1u` — $1$.

*Ключ:* маска беззнаковая (`1u`), чтобы для старших $k$ сдвиг не переполнял `int`, а `~` маски давал единицы во всех битах, кроме $k$.

*Ответ:* $180$, $176$, $176$, $1$.
:::

::: {.problem #prob:lec04:power-of-two}
Запиши выражение без циклов, равное `1`, если беззнаковое `x` — степень двойки ($1, 2, 4, \dots$), и `0` иначе. Проверь его на `64`, `96`, `1`, `0`.
:::

::: solution
*Ключ:* у степени двойки в двоичной записи ровно одна единица, а `x & (x - 1)` сбрасывает младшую единицу. Значит, у степени двойки после этого остается $0$, а у числа с двумя и более единицами — нет. Отдельно нужно исключить `x = 0`: у него единиц нет, а `0 & (0u - 1)` тоже `0`.

Выражение: `x != 0 && (x & (x - 1)) == 0`. Скобки вокруг `x & (x - 1)` обязательны: без них `==` выполнилось бы раньше `&`.

- `64` $= 1000000_2$, `64 & 63` $= 0$ — `1`;
- `96` $= 1100000_2$, `96 & 95` $= 1000000_2 = 64 \ne 0$ — `0`;
- `1` $= 2^0$, `1 & 0` $= 0$ — `1`;
- `0` — левый операнд `&&` ложен — `0`.

*Ответ:* `x != 0 && (x & (x - 1)) == 0`; на `64`, `96`, `1`, `0` получается `1`, `0`, `1`, `0`.
:::

::: {.problem #prob:lec04:bit-groups}
`unsigned` 32-битный, `x = 0xABCDEF12`. Запиши выражения и вычисли их:

- (а) обнулить $12$ младших бит;
- (б) инвертировать биты с $8$-го по $15$-й;
- (в) обнулить $k$ младших бит, $0 \le k < 32$ (вычисли при $k = 5$).
:::

::: solution
*Ключ:* маску группы битов удобно писать в шестнадцатеричной записи: одна цифра — четыре бита.

- (а) $12$ младших бит — три младшие шестнадцатеричные цифры, маска `0xFFFu`. Сбросить их: `x & ~0xFFFu`, получается `0xABCDE000`.
- (б) Биты $8$–$15$ — вторая снизу пара цифр, маска `0xFF00u`. `^` с единицами инвертирует: `x ^ 0xFF00u`. Байт `0xEF` превращается в `0x10`, получается `0xABCD1012`.
- (в) `(1u << k) - 1` — $k$ младших единиц, `~` дает маску с нулями в них: `x & ~((1u << k) - 1)`. При $k = 5$ маска `~0x1Fu`, младшая цифра `2` и бит $4$ обнуляются: `0xABCDEF00`. При $k = 32$ сдвиг не определен, этот случай пришлось бы разбирать отдельно.

*Ответ:*

- (а) `x & ~0xFFFu`, значение `0xABCDE000`;
- (б) `x ^ 0xFF00u`, значение `0xABCD1012`;
- (в) `x & ~((1u << k) - 1)`, при $k = 5$ значение `0xABCDEF00`.
:::

::: {.problem #prob:lec04:byte-swap}
`unsigned` 32-битный. Запиши выражение, которое переставляет байты `x` в обратном порядке: из `0x12345678` должно получиться `0x78563412`.
:::

::: solution
*Ключ:* каждый байт сдвигаем на его новое место и вырезаем маской, чтобы отбросить соседние биты:

```c
(x >> 24) | ((x >> 8) & 0xFF00u) | ((x << 8) & 0xFF0000u) | (x << 24)
```

Старший байт уходит вниз на $24$ бита, младший — вверх на $24$; у двух средних сдвиг $8$ бит, и маска отбрасывает соседей. Для `0x12345678` получается `0x78563412`. Так переводят число между little-endian и big-endian, например в сетевой порядок байтов (определение [-@def:lec03:network-order]) на машине x86.
:::

::: {.problem #prob:lec04:parens}
Убери лишние скобки, не меняя смысла выражения:

- (а) `d ^= ((a & b) | c)`;
- (б) `x = (((a < b) ? (a + 1) : b) - 1)`;
- (в) `(x >> (y & 0xF)) & 0xF`;
- (г) `i = ((i++) + (++i))`.
:::

::: solution
*Ключ:* по таблице приоритетов проверить каждую пару скобок: нужна она только там, где без неё раньше выполнилась бы операция снаружи.

(а) `&` старше `|`, а оба старше `^=`: `d ^= a & b | c`. `gcc -Wall` на такую запись предупреждает (`suggest parentheses around arithmetic in operand of '|'`): лишние для компилятора скобки помогают читателю.

(б) Сравнение и сложение старше `?:`, присваивание младше: `x = (a < b ? a + 1 : b) - 1`. Скобки вокруг условной операции нужны: `-` старше `?:`, и без них получилось бы `a < b ? a + 1 : (b - 1)`.

(в) `>>` старше `&`: `x >> (y & 0xF) & 0xF`. Внутренние скобки нужны, иначе сдвиг выполнится раньше `&`.

(г) Постфиксный и префиксный `++` старше `+`: `i = i++ + ++i`. Смысл не изменился, но его и не было: `i` меняется трижды без точки следования, это неопределенное поведение.
:::

::: {.problem #prob:lec04:common-type}
`int` 4 байта, `long` 8. Даны `unsigned u = 3; int i = -5; long l = -5;`. Найди тип и значение выражений:

- (а) `u + i`;
- (б) `u + l`;
- (в) `i < u`;
- (г) `l < u`.
:::

::: solution
*Ключ:* для каждой пары найти правило обычных арифметических преобразований, затем считать уже в общем типе.

- (а) `unsigned int` и `int` одного ранга — правило 4: `i` становится $2^{32} - 5$; $3 + 2^{32} - 5 = 2^{32} - 2$. Тип `unsigned int`, значение $4294967294$.
- (б) `long` вмещает все значения `unsigned int` — правило 5: `u` становится `long`, $3 + (-5) = -2$. Тип `long`.
- (в) Правило 4: сравниваются $2^{32} - 5$ и $3$, первое больше. Результат `0` типа `int`.
- (г) Правило 5: сравниваются $-5$ и $3$ как `long`. Результат `1`.

*Ответ:*

- (а) `unsigned int`, $4294967294$;
- (б) `long`, $-2$;
- (в) `int`, $0$;
- (г) `int`, $1$.
:::

::: {.problem #prob:lec04:promotion}
Дано `unsigned char c = 0x0F;` (`int` — 4 байта). Найди тип и значение `~c` и `c << 4`, значение `sizeof(c << 4)`, а также значение `d` после `unsigned char d = ~c;`.
:::

::: solution
*Ключ:* перед `~` и `<<` операнд типа `unsigned char` продвигается в `int`, и операция идет над 32 битами.

- `~c`: `c` становится `int` $15 =$ `0x0000000F`, инверсия дает `0xFFFFFFF0`, в `int` (дополнительный код) это $-16$. Тип `int`.
- `c << 4`: $15 \cdot 16 = 240$, помещается в `int`. Тип `int`.
- `sizeof(c << 4)` равно `sizeof(int)`, то есть $4$.
- `d = ~c`: значение $-16$ записывается в `unsigned char` по модулю $2^8$: $-16 + 256 = 240$.

*Ответ:* `~c` — `int` $-16$; `c << 4` — `int` $240$; `sizeof(c << 4)` равно $4$; `d` равно $240$.
:::

::: {.problem #prob:lec04:average}
Программа считает среднее: `int sum = 17, n = 4; double avg = sum / n;`. Что окажется в `avg`? Исправь инициализацию так, чтобы получилось точное среднее, и объясни, почему `(double)(sum / n)` не помогает.
:::

::: solution
`sum / n` — деление двух `int`, оно целое: `17 / 4` равно `4`, в `avg` записывается `4.0`.

*Ключ:* привести к `double` операнд *до* деления, тогда по правилу 1 обычных преобразований второй операнд тоже станет `double`: `double avg = (double) sum / n;` дает $4{,}25$. Приведение связывает сильнее `/`, поэтому приводится именно `sum`.

В `(double)(sum / n)` скобки заставляют сначала выполнить целое деление, приводится уже готовое `4`, получается `4.0`.
:::

::: {.problem #prob:lec04:printf-format}
Что напечатает `printf("[%4d|%-4d|%04d|%x]\n", 7, 7, 7, 255u);`?
:::

::: solution
*Ключ:* ширина $4$: `%4d` дополняет пробелами слева, `%-4d` — справа, `%04d` — нулями; $255 = \mathrm{FF}_{16}$ (`%x` печатает строчными буквами). Программа печатает `[   7|7   |0007|ff]`.
:::

::: {.problem #prob:lec04:io}
Программа из примера [-@ex:lec04:scanf-check] получает на вход:

- (а) `40 2`;
- (б) `-5`, перевод строки, `5`;
- (в) `7 x`;
- (г) `3.9 1`.

Что она напечатает в каждом случае?
:::

::: solution
*Ключ:* `%d` пропускает любые пробельные символы перед числом и останавливается на первом символе, который не может продолжить число.

- (а) Прочитаны оба числа, печатается `42`.
- (б) Перевод строки пропускается так же, как пробел, печатается `0`.
- (в) Первое число прочитано, на `x` второе чтение не удается, `got = 1`; печатается `ошибка: ожидались два целых числа (прочитано 1)`.
- (г) Первый `%d` читает `3` и останавливается на точке; второй `%d` начинает с точки и не может прочитать число, `got = 1`; печатается `ошибка: ожидались два целых числа (прочитано 1)`.
:::

::: {.problem #prob:lec04:io-specifiers}
Какими спецификаторами читать через `scanf` переменные `short s; long l; double d;` и какими печатать их через `printf`?
:::

::: solution
*Ключ:* в `scanf` тип спецификатора обязан совпадать с типом переменной точно (продвижения нет), а в `printf` `short` продвигается в `int`, `float` — в `double`.

*Ответ:*

- `scanf`: `%hd`, `%ld`, `%lf`;
- `printf`: `%hd` (или `%d`), `%ld`, `%f`.
:::

# Итоги

- Область действия и класс памяти независимы: `static`-переменная в функции видна только там, но живет всю программу и помнит значение между вызовами. Без инициализатора статические переменные равны нулю, а значение автоматических не определено.
- Тип константы читается по записи: префикс задает систему счисления (`0` — восьмеричная, `0x` — шестнадцатеричная, `0b` — двоичная), суффиксы `u`, `l`, `ll` — тип; символьная константа в C имеет тип `int`.
- Деление двух целых — целое, с округлением к нулю, а остаток имеет знак делимого; остаток из $[0, b)$ дает `(a % b + b) % b`.
- Беззнаковая арифметика идет по модулю $2^N$; знаковое переполнение, сдвиг за ширину типа и деление на ноль — неопределенное поведение, на которое компилятор вправе опираться.
- `&&` и `||` вычисляют правый операнд, только если результат еще не ясен, и между операндами стоит точка следования; в остальных местах переменную между двумя точками следования можно изменить только один раз: `i++ + ++i` и `i = i++` — неопределенное поведение.
- Присваивание в C — выражение со значением, поэтому работает цепочка `a = b = 0`; у `x++` значение старое, у `++x` — новое.
- Поразрядные операции стоят ниже сравнений, поэтому в проверках битов нужны скобки; бит $k$ проверяют, ставят и сбрасывают маской `1u << k`.
- Тип операции определяют операнды: короткие типы продвигаются в `int`, при смешении знакового и беззнакового одной ширины выигрывает беззнаковый (`-1 < 0u` ложно), а чтобы деление стало вещественным, операнд приводят до деления: `(double) a / b`.
