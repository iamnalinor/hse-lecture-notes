# Контекст

На прошлой лекции разобраны выражения: операции над целыми, ленивое вычисление `&&` и `||` (определение [-@def:lec04:short-circuit]), присваивание как выражение со значением и точки следования (определение [-@def:lec04:sequence-point]). Там же собраны правила приведения типов, поразрядные операции, переполнение и форматный ввод-вывод через `printf` и `scanf`. Выражение вычисляет значение, а программе нужно еще решать, что делать дальше: выполнить один из вариантов, повторить действия, выйти из цикла. Для этого служат операторы. Эта лекция о том, как они устроены в C: составной оператор, `if`, `switch`, циклы `while`, `do`–`while`, `for` и операторы перехода `break`, `continue`, `goto`. В каждом есть своя ловушка, и почти все они видны компилятору, если включить предупреждения.

# После прочтения ты сможешь

- определить, к какому `if` относится `else`, и найти ошибку, когда тело `if` или цикла оказалось пустым из-за лишней `;`;
- проследить выполнение `switch` с `break` и без него;
- найти, сколько раз выполнится тело цикла `while`, `do`–`while` или `for`, и чему равны переменные после выхода;
- переписать цикл `for` через `while` так, чтобы `continue` работал так же;
- предсказать вывод цикла с `break` и `continue` и выйти сразу из нескольких вложенных циклов;
- проследить цикл, который читает числа до конца ввода, и записать цикл с беззнаковым счетчиком, идущий вниз до нуля;
- записать условие високосного года и вычислить номер дня в году.

# Теория

## Выражение, блок и пустой оператор

Оператор (определение [-@def:lec04:expression]) — конструкция, которая выполняется, а не вычисляется. Простейшие операторы такие.

::: {.definition #def:lec05:statement title="выражение-оператор, составной и пустой оператор"}
- *Выражение-оператор* `выражение;` вычисляет выражение и отбрасывает его значение; полезен он только побочным эффектом: `x = 5;`, `i++;`, `printf("hi\n");`.
- *Пустой оператор* `;` не делает ничего.
- *Составной оператор* (блок) `{ … }` — последовательность объявлений и операторов в фигурных скобках. Там, где синтаксис требует одного оператора, блок позволяет написать несколько.
:::

Блок — это и область действия (определение [-@def:lec04:scope]): переменная, объявленная внутри `{ … }`, видна до закрывающей скобки и, если она автоматическая, живет до выхода из блока.

Точку с запятой в C ставят в конце выражения-оператора, а не между операторами. Поэтому после `}` блока `;` не нужна; если её поставить, получится лишний пустой оператор. Обычно он безвреден, а в двух местах ниже ломает программу.

## Условный оператор `if`

::: {.definition #def:lec05:if title="условный оператор"}
`if (выражение) оператор1` вычисляет выражение и выполняет `оператор1`, если значение не равно нулю. `if (выражение) оператор1 else оператор2` при нулевом значении выполняет `оператор2`. Скобки вокруг условия обязательны, а каждая ветка — ровно один оператор; чтобы выполнить несколько, их объединяют в блок.
:::

Условие — любое выражение целого или вещественного типа (позже — и указатель): истина — всё, что не ноль (раздел [-@sec:lec04:logical]). Поэтому `if (x)` значит то же, что `if (x != 0)`, а `if (!x)` — то же, что `if (x == 0)`. После вычисления условия стоит точка следования, так что все его побочные эффекты закончены до того, как начнется ветка.

Цепочка проверок записывается через `else if`. Отдельной конструкции для неё нет: это `if`, вложенный в ветку `else` предыдущего.

```c
if (d < 0)
    printf("Решений нет\n");
else if (d == 0)
    printf("Одно решение\n");
else
    printf("Два решения\n");
```

::: {.example #ex:lec05:quadratic title="квадратное уравнение"}
Программа читает целые коэффициенты $a$, $b$, $c$ и решает $ax^2 + bx + c = 0$.

```c
#include <stdio.h>
#include <math.h>

int main(void)
{
    int a, b, c, d;
    if (scanf("%d%d%d", &a, &b, &c) != 3) {
        printf("Нужно ввести три коэффициента\n");
        return 1;
    }
    if (!a) {
        printf("Уравнение не квадратное\n");
        return 1;
    }
    d = b * b - 4 * a * c;
    if (d < 0)
        printf("Решений нет\n");
    else if (d == 0) {
        double db = -b;
        printf("Решение: %.4f\n", db / (2 * a));
    } else {
        double db = -b;
        double dd = sqrt(d);
        printf("Решение 1: %.4f, решение 2: %.4f\n",
               (db + dd) / (2 * a), (db - dd) / (2 * a));
    }
    return 0;
}
```

Функция `sqrt` объявлена в `math.h`; в Linux при сборке нужен ключ `-lm`: `gcc -Wall -Wextra quad.c -o quad -lm`. На вводе `1 -3 2` программа печатает `Решение 1: 2.0000, решение 2: 1.0000`, на `1 2 1` — `Решение: -1.0000`, на `0 1 1` — сообщение о том, что уравнение не квадратное, с кодом завершения $1$.

Деление `db / (2 * a)` вещественное, потому что `db` типа `double` (правило 1 определения [-@def:lec04:usual-conversions]); если бы делили `-b / (2 * a)`, получилось бы целое частное. Переменные `db` и `dd` объявлены внутри блоков и видны только в своей ветке.
:::

::: {.remark #rem:lec05:quadratic-overflow tag="корнер-кейс"}
Дискриминант считается в `int`, и при больших коэффициентах `b * b` переполняется: уже при `b = 50000` произведение $2{,}5 \cdot 10^9$ больше `INT_MAX`, а это неопределенное поведение (определение [-@def:lec04:overflow]). Если коэффициенты могут быть большими, дискриминант считают в `long long` или в `double`, причем операнды расширяют до умножения: `(long long)b * b - 4LL * a * c`. Одного `long long d` мало: `b * b` и `4 * a * c` всё равно вычислятся в `int` и переполнятся до присваивания. Каждое промежуточное значение тоже должно помещаться в выбранный тип. Это касается и `-b` с `2 * a` в программе выше: они тоже вычисляются в `int`, поэтому `-b` при `b = INT_MIN` и `2 * a` при $a \geq 2^{30}$ переполняются, даже если дискриминант посчитан в `long long`. При коэффициентах около `INT_MAX` не спасает и `long long`: $4ac$ доходит до $2^{64}$, а `LLONG_MAX` — это $2^{63} - 1$. Надежнее перейти в `double` до операции: `-(double)b`, `2.0 * a`, дискриминант в `double` (младшие цифры могут потеряться, но переполнения не будет).
:::

::: {.remark #rem:lec05:dangling-else tag="подводный камень"}
`else` относится к ближайшему `if` без своего `else`, и отступы на это не влияют. В записи

```c
if (x > 2)
    if (y > z)
        y = z;
else
    z = y;
```

`else` принадлежит внутреннему `if (y > z)`, хотя стоит под внешним. При `x = 1` не выполняется ничего. Чтобы `else` относился к внешнему `if`, внутренний `if` заключают в блок:

```c
if (x > 2) {
    if (y > z)
        y = z;
}
else
    z = y;
```

`gcc -Wall` предупреждает о таком месте: `suggest explicit braces to avoid ambiguous 'else'`.
:::

::: {.remark #rem:lec05:empty-body tag="подводный камень"}
Лишняя `;` после условия делает пустой оператор телом `if`:

```c
if (y > 10);
{
    puts("big");
}
```

Здесь тело `if` — пустой оператор, а блок с `puts` — следующий оператор, который выполняется всегда, при любом `y`. `gcc -Wextra` предупреждает: `suggest braces around empty body in an 'if' statement`. Та же ошибка с циклом, `for (i = 0; i < 5; i++);`, превращает цикл в пустой. Еще одна ловушка условий — присваивание вместо сравнения, `if (x = 1)` (замечание [-@rem:lec04:assign-in-condition]).
:::

## Оператор выбора `switch`

Когда нужно выбрать действие по значению одного целого выражения из нескольких констант, цепочку `else if` заменяет `switch`.

::: {.definition #def:lec05:switch title="оператор выбора"}
```c
switch (выражение) {
case константа1: операторы
case константа2: операторы
default: операторы
}
```

Выражение должно быть целого типа (`char` и `_Bool` тоже целые), после `case` — целые константные выражения, все разные. `switch` вычисляет выражение и передает управление на метку `case` с равным значением, а если такой нет — на `default`; если нет и `default`, тело пропускается. Оператор `break` внутри `switch` сразу выходит из него.
:::

Метки `case` — только места, куда можно прыгнуть, а не границы вариантов. После перехода выполнение идет подряд по всем операторам тела, через следующие `case`, пока не встретит `break` или конец `switch`. Это называется *проваливанием* (fall-through).

```c
int n = 1;
switch (n) {
case 1: printf("one ");
case 2: printf("two ");
default: printf("other ");
}
```

Этот фрагмент печатает `one two other`. Чтобы выполнился только вариант `case 1`, в конце каждого варианта ставят `break;`.

::: {.remark #rem:lec05:fallthrough tag="подводный камень"}
Забытый `break` — частая ошибка, поэтому `gcc -Wextra` предупреждает о каждом проваливании: `this statement may fall through`. Если проваливание задумано, это помечают. В C23 для этого есть атрибут `[[fallthrough]];` перед следующей меткой; GCC понимает и комментарий `/* fallthrough */` в том же месте, а Clang — только атрибут. Несколько меток подряд без операторов между ними (`case 9: case 10:`) проваливанием не считаются, и предупреждения нет.
:::

Проваливание бывает и полезным: тогда варианты подбирают так, чтобы каждый добавлял свою часть, а следующие — остальное.

::: {.example #ex:lec05:day-of-year title="номер дня в году"}
Номер дня $d$ месяца $m$ равен $d$ плюс число дней во всех месяцах до $m$-го. Начнем выполнение с метки месяца $m$ и будем проваливаться вниз, прибавляя по месяцу:

```c
static int leap_year(int y)
{
    return (y % 400 == 0) || (y % 4 == 0 && y % 100 != 0);
}

static int days_from_jan1(int d, int m, int y)
{
    int days = 0;
    switch (m) {
    case 12: days += 30;    /* ноябрь */
    case 11: days += 31;    /* октябрь */
    case 10: days += 30;    /* сентябрь */
    case 9:  days += 31;    /* август */
    case 8:  days += 31;    /* июль */
    case 7:  days += 30;    /* июнь */
    case 6:  days += 31;    /* май */
    case 5:  days += 30;    /* апрель */
    case 4:  days += 31;    /* март */
    case 3:  days += leap_year(y) ? 29 : 28;    /* февраль */
    case 2:  days += 31;    /* январь */
    case 1:  break;
    }
    return days + d;
}
```

Для 24 ноября 2026 года выполнение начинается с `case 11` и прибавляет октябрь, сентябрь и так далее до января: $31 + 30 + 31 + 31 + 30 + 31 + 30 + 31 + 28 + 31 = 304$, ответ $304 + 24 = 328$. Для 1 марта 2024 года (високосный) — $29 + 31 + 1 = 61$, для 1 марта 2026 года — $60$. Слово `static` перед функцией прячет её имя от других файлов программы, как у глобальной переменной (раздел [-@sec:lec04:variables]).

Год високосный, если он делится на $400$ или делится на $4$, но не на $100$. `leap_year` возвращает значение этого условия, то есть `0` или `1` типа `int`: 1900 и 2026 — `0`, 2000 и 2024 — `1`. Каждый вариант этого `switch` проваливается в следующий, и `gcc -Wextra` предупредит о каждом. В программе, которую собирают с `-Werror`, перед каждой меткой ставят `[[fallthrough]];`.
:::

## Циклы

::: {.definition #def:lec05:while title="циклы while и do–while"}
- `while (выражение) оператор` — *цикл с предусловием*: вычисляет выражение; если оно не ноль, выполняет оператор (тело) и снова вычисляет выражение, и так пока выражение не станет нулем. Если условие ложно сразу, тело не выполняется ни разу.
- `do оператор while (выражение);` — *цикл с постусловием*: сначала выполняет тело, потом вычисляет выражение и повторяет, пока оно не ноль. Тело выполняется хотя бы один раз.
:::

`do`–`while` нужен, когда условие можно проверить только после первого прохода: например, ввод повторяют, пока он не станет правильным. Если `k = 10`, цикл `do { k++; } while (k < 5);` выполнит тело один раз, а `while (k < 5) k++;` — ни разу.

Типичный цикл чтения: `scanf` возвращает число прочитанных значений (раздел [-@sec:lec04:io]), и цикл продолжается, пока очередное число прочитано.

```c
int x, sum = 0;
while (scanf("%d", &x) == 1)
    sum += x;
printf("%d\n", sum);
```

На вводе `10 -2 7` печатается `15`. На вводе `3 4 x 5` — `7`: на символе `x` `scanf` возвращает `0`, и цикл кончается. Цикл без условия выхода пишут как `while (1)`, а выходят из него оператором `break` (ниже).

::: {.definition #def:lec05:for title="цикл for"}
`for (выражение1; выражение2; выражение3) оператор` выполняется так:

1. один раз вычисляется `выражение1` (инициализация);
2. вычисляется `выражение2` (условие); если оно ноль, цикл кончается;
3. выполняется тело, затем вычисляется `выражение3` (шаг), и снова шаг 2.

Любое из трех выражений можно опустить; пропущенное условие считается истинным, поэтому `for (;;)` — бесконечный цикл. С C99 вместо `выражения1` можно написать объявление: `for (int i = 0; i < n; i++)`; область действия такой `i` — только цикл.
:::

Без `continue` (ниже) цикл `for` равносилен такому `while`:

```c
{
    выражение1;
    while (выражение2) {
        оператор
        выражение3;
    }
}
```

Блок нужен, чтобы объявление из `выражения1` (C99) оставалось видимым только внутри цикла, как в `for`. Запись верна, когда все три выражения заданы; пропущенное условие заменяют на `1`, остальные части просто не пишут.

`for` удобен, когда у цикла есть счетчик: всё, что управляет повторением, собрано в одной строке, и шаг не потеряется в длинном теле. Например, `for (int i = 0; i < 10; i += 3)` проходит $i = 0, 3, 6, 9$ — четыре раза. В заголовке часто используют операцию запятая (раздел [-@sec:lec04:compound]): `for (i = 0, j = n - 1; i < j; i++, j--)` двигает два счетчика навстречу друг другу.

::: {.remark #rem:lec05:unsigned-countdown tag="подводный камень"}
Цикл по беззнаковому счетчику вниз до нуля включительно, `for (unsigned i = n; i >= 0; i--)`, не кончается: `i >= 0` истинно для любого беззнакового `i`, и после $0$ счетчик становится `UINT_MAX` (замечание [-@rem:lec04:sizeof-compare]). Правильно уменьшать счетчик в условии: `for (unsigned i = n; i-- > 0; )` — условие сравнивает старое значение, а тело видит уже уменьшенное. При `n = 3` тело выполняется для $i = 2, 1, 0$, и цикл кончается.
:::

## Операторы перехода

::: {.definition #def:lec05:jumps title="break, continue, goto"}
- `break;` немедленно выходит из ближайшего объемлющего цикла или `switch`.
- `continue;` заканчивает текущий проход ближайшего объемлющего цикла: в `while` и `do`–`while` управление переходит к проверке условия, в `for` — к `выражению3`, а потом к условию.
- `goto метка;` передает управление оператору с этой меткой, `метка: оператор`. Метка видна во всей функции, где она стоит, в том числе выше неё по тексту, а в других функциях — нет.
:::

```c
for (int j = 1; j <= 10; j++) {
    if (j % 4 == 0)
        continue;           /* пропустить 4 и 8 */
    if (j * j > 40)
        break;              /* выйти при j = 7 */
    printf("%d ", j);
}
```

Фрагмент печатает `1 2 3 5 6`: при $j = 4$ `continue` пропускает печать, при $j = 7$ квадрат $49 > 40$, и `break` завершает цикл.

::: {.remark #rem:lec05:for-continue tag="подводный камень"}
Из-за `continue` переписывание `for` в `while` по схеме выше не всегда равносильно. В `for` `continue` переходит к шагу `выражение3`, а в `while` шаг стоит в конце тела, и `continue` его перепрыгивает. Цикл

```c
int s = 0, i = 1;
while (i <= 6) {
    if (i % 2 == 0)
        continue;
    s += i;
    i++;
}
```

при $i = 2$ зацикливается: `i++` больше не выполняется. Перед `continue` в таком `while` шаг нужно повторить: `if (i % 2 == 0) { i++; continue; }`.
:::

`break` выходит только из одного цикла. Чтобы выйти сразу из нескольких вложенных, заводят флаг и проверяют его в условии каждого внешнего цикла или используют `goto`. Это один из немногих случаев, где `goto` делает код проще.

::: {.example #ex:lec05:nested-exit title="выход из вложенных циклов"}
Найти первую пару $(i, j)$, $1 \le i, j \le 5$, у которой $i \cdot j = 12$, перебирая $i$ во внешнем цикле:

```c
int fi = -1, fj = -1;
for (int i = 1; i <= 5; i++)
    for (int j = 1; j <= 5; j++)
        if (i * j == 12) {
            fi = i;
            fj = j;
            goto found;
        }
found:
printf("%d %d\n", fi, fj);    /* 3 4 */
```

При $i = 1, 2$ подходящего $j \le 5$ нет ($12 / 1$ и $12 / 2$ больше $5$), при $i = 3$ находится $j = 4$, и `goto` выходит из обоих циклов. С `break` вместо `goto` внутренний цикл кончился бы, а внешний продолжился бы и дошел до пары $(4, 3)$.
:::

Без нужды `goto` не используют: переходы назад и через несколько уровней превращают программу в клубок, по которому трудно понять, какой код выполнится. Почти всегда хватает `if`, циклов, `break` и `continue`.

# Практика

::: {.problem #prob:lec05:dangling-else}
`int x = -5, y = -2;`. Что напечатает фрагмент? Расставь фигурные скобки так, чтобы `else` относился к внешнему `if`, и найди вывод снова.

```c
if (x > 0)
    if (y > 0)
        puts("3");
else
    puts("4");
```
:::

::: solution
*Ключ:* `else` принадлежит ближайшему `if` без `else`, отступы не считаются.

Фрагмент равносилен `if (x > 0) { if (y > 0) puts("3"); else puts("4"); }`. Условие `x > 0` ложно, внешний `if` ничего не выполняет, и фрагмент ничего не печатает.

Со скобками `if (x > 0) { if (y > 0) puts("3"); } else puts("4");` ложное внешнее условие ведет в `else`, и печатается `4`.
:::

::: {.problem #prob:lec05:empty-body}
Что напечатает фрагмент и почему?

```c
int i;
for (i = 0; i < 5; i++);
    printf("%d\n", i);
```
:::

::: solution
*Ключ:* `;` сразу после заголовка — пустой оператор, и он и есть тело цикла.

Цикл с пустым телом прокручивает `i` от $0$ до $5$ и кончается, когда `i < 5` становится ложным. `printf` — уже следующий оператор, отступ ничего не значит; он выполняется один раз и печатает `5`. `gcc -Wall` предупреждает: `this 'for' clause does not guard...`.
:::

::: {.problem #prob:lec05:switch-trace}
Чему равна `grade(s)` для `s` $= 100, 95, 84, 71, 40$?

```c
int grade(int s)
{
    int bonus = 0;
    switch (s / 10) {
    case 10:
    case 9:
        bonus += 3;
    case 8:
        bonus += 2;
        break;
    case 7:
        bonus += 1;
    default:
        bonus += 0;
    }
    return bonus;
}
```
:::

::: solution
*Ключ:* найти метку, куда прыгает `switch`, и выполнять всё подряд до `break` или конца.

- $100$: `s / 10` $= 10$, проваливание в `case 9` ($+3$) и `case 8` ($+2$), затем `break`: $5$.
- $95$: `case 9`, так же $3 + 2 = 5$.
- $84$: `case 8`: $2$.
- $71$: `case 7` ($+1$), проваливание в `default` ($+0$): $1$.
- $40$: метки `case 4` нет, переход на `default`: $0$.
:::

::: {.problem #prob:lec05:loop-count}
Сколько раз выполнится тело каждого цикла и чему равно `k` после последнего?

- (а) `for (k = 1; k < 100; k *= 3) a++;`
- (б) `k = 20; do { b++; k -= 7; } while (k > 0);`
- (в) `k = 5; while (k-- > 0) c++;`
:::

::: solution
*Ключ:* выписать значения счетчика в момент каждой проверки условия.

- (а) Условие проверяется при $k = 1, 3, 9, 27, 81$ (истинно) и $k = 243$ (ложно): тело выполняется $5$ раз, после цикла $k = 243$.
- (б) Тело выполняется до проверки: $k = 20 \to 13 \to 6 \to -1$; после третьего прохода $-1 > 0$ ложно. Три раза, $k = -1$.
- (в) `k-- > 0` сравнивает старое значение: проверки при $k = 5, 4, 3, 2, 1$ истинны, при $k = 0$ ложна, но уменьшение происходит и в ней. Пять раз, после цикла $k = -1$.
:::

::: {.problem #prob:lec05:for-while}
Перепиши цикл через `while` так, чтобы результат `s` не изменился, и найди `s`.

```c
int s = 0;
for (int i = 1; i <= 6; i++) {
    if (i % 2 == 0)
        continue;
    s += i;
}
```
:::

::: solution
*Ключ:* в `for` `continue` ведет к шагу `i++`, а в `while` шаг стоит в конце тела, поэтому его нужно выполнить и перед `continue`.

```c
int s = 0, i = 1;
while (i <= 6) {
    if (i % 2 == 0) {
        i++;
        continue;
    }
    s += i;
    i++;
}
```

Оба цикла складывают нечетные числа до $6$: $s = 1 + 3 + 5 = 9$. Без `i++` перед `continue` цикл `while` при $i = 2$ зациклился бы (замечание [-@rem:lec05:for-continue]).
:::

::: {.problem #prob:lec05:break-continue}
Что напечатает фрагмент?

```c
for (int n = 10; n > 0; n -= 3) {
    if (n == 7)
        continue;
    if (n < 3)
        break;
    printf("%d ", n);
}
```
:::

::: solution
*Ключ:* `continue` в `for` всё равно выполняет шаг `n -= 3`.

Значения $n$: $10$ — печатается; $7$ — `continue`, печати нет, шаг дает $4$; $4$ — печатается; $1$ — `1 < 3`, `break`. Вывод: `10 4`.
:::

::: {.problem #prob:lec05:nested-exit}
Перепиши пример [-@ex:lec05:nested-exit] без `goto`, с флагом `found`, так, чтобы ответ остался `3 4`.
:::

::: solution
*Ключ:* `break` выходит из внутреннего цикла, а внешний должен проверять флаг в условии.

```c
int fi = -1, fj = -1, found = 0;
for (int i = 1; i <= 5 && !found; i++)
    for (int j = 1; j <= 5; j++)
        if (i * j == 12) {
            fi = i;
            fj = j;
            found = 1;
            break;
        }
printf("%d %d\n", fi, fj);
```

При $i = 3$, $j = 4$ флаг становится `1`, `break` выходит из внутреннего цикла; внешний делает шаг `i++`, проверяет `!found`, получает `0` и тоже заканчивается. Печатается `3 4`.
:::

::: {.problem #prob:lec05:read-loop}
Программа из раздела о циклах (сумма чисел до конца ввода) получает ввод `5 -3 12.5 4`. Что она напечатает?
:::

::: solution
*Ключ:* цикл идет, пока `scanf` возвращает `1`, а `%d` останавливается на первом символе, который не продолжает целое число.

Читаются $5$ и $-3$. Третий вызов читает `12` и останавливается на точке, `scanf` возвращает `1`, сумма $14$. Четвертый вызов начинает с `.`, прочитать целое не может и возвращает `0`; цикл кончается, `4` не читается. Печатается `14`.
:::

::: {.problem #prob:lec05:countdown}
Нужно напечатать числа от `n - 1` до `0` по убыванию, `n` типа `unsigned`. Что не так с циклом `for (unsigned i = n - 1; i >= 0; i--) printf("%u ", i);`? Как его исправить и что выведет исправленный цикл при `n = 3` и при `n = 0`?
:::

::: solution
*Ключ:* беззнаковое `i >= 0` всегда истинно, а после $0$ уменьшение дает `UINT_MAX`.

Цикл не останавливается: после $0$ счетчик становится `UINT_MAX` (при 32-битном `unsigned` это $4294967295$), условие снова истинно. Исправление — уменьшать счетчик в условии: `for (unsigned i = n; i-- > 0; ) printf("%u ", i);`. При `n = 3` печатается `2 1 0`. При `n = 0` первое же условие сравнивает $0 > 0$, оно ложно, и не печатается ничего. Исходный цикл при `n = 0` начал бы вообще с `0u - 1`, то есть с `UINT_MAX`.
:::

::: {.problem #prob:lec05:leap-year}
Чему равны `leap_year(y)` из примера [-@ex:lec05:day-of-year] для $y = 1900, 2000, 2024, 2100$? Можно ли записать условие как `y % 4 == 0 && y % 100 != 0 || y % 400 == 0`, без скобок?
:::

::: solution
- $1900$: делится на $4$ и на $100$, на $400$ не делится — `0`.
- $2000$: делится на $400$ — `1`.
- $2024$: делится на $4$, не делится на $100$ — `1`.
- $2100$: как 1900 — `0`.

*Ключ:* `&&` старше `||`, поэтому запись без скобок читается как `(y % 4 == 0 && y % 100 != 0) || y % 400 == 0` и означает то же самое. Записать так можно, скобки нужны только читателю; `gcc -Wall` предлагает их поставить (`suggest parentheses around '&&' within '||'`).
:::

::: {.problem #prob:lec05:day-of-year}
Вычисли `days_from_jan1(15, 4, 2025)` и `days_from_jan1(31, 12, 2024)` из примера [-@ex:lec05:day-of-year]. Какие метки `case` пройдет выполнение в первом вызове?
:::

::: solution
*Ключ:* выполнение начинается с метки месяца и проходит все метки ниже, прибавляя дни предыдущих месяцев.

- `days_from_jan1(15, 4, 2025)`: метки `case 4` (март, $31$), `case 3` (февраль 2025 года, не високосного, $28$), `case 2` (январь, $31$), `case 1` (`break`). $31 + 28 + 31 + 15 = 105$.
- `days_from_jan1(31, 12, 2024)`: все месяцы с января по ноябрь, февраль високосный: $30 + 31 + 30 + 31 + 31 + 30 + 31 + 30 + 31 + 29 + 31 = 335$, плюс $31$ — $366$, последний день високосного года.
:::

# Итоги

- Каждая ветка `if` и тело цикла — один оператор; несколько операторов собирают в блок `{ … }`, а лишняя `;` после условия или заголовка цикла становится пустым телом.
- `else` относится к ближайшему `if` без `else`, отступы не важны; если нужно иначе, ставят фигурные скобки.
- `case` в `switch` — только метка входа: без `break` выполнение проваливается в следующие варианты, и задуманное проваливание помечают `[[fallthrough]];`.
- `while` проверяет условие до тела и может не выполнить его ни разу, `do`–`while` выполняет тело хотя бы один раз.
- `for (e1; e2; e3)` — это `e1; while (e2) { тело; e3; }`, только `continue` в `for` ведет к шагу `e3`, а в таком `while` перепрыгивает его.
- `break` выходит только из одного цикла или `switch`; из нескольких вложенных выходят флагом или `goto`.
- Беззнаковый счетчик вниз до нуля уменьшают в условии: `for (unsigned i = n; i-- > 0; )`.
