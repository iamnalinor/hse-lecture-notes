## Что здесь есть

- **Конспекты лекций.** Каждая лекция — связный текст. Он идет за лекцией, но не пересказывает её дословно: определения, теоремы с доказательствами, примеры, замечания о частых ошибках, разобранные задачи и итоги.
- **Теория курса.** Все определения и утверждения семестра по лекциям, у теорем — идея доказательства. Удобно повторить за час перед контрольной.
- **Подготовка к КР и коллоквиуму.** Темы, методы, задачи с решениями, генератор билетов, шпаргалки в PDF.
- **ПУД.** Формула оценки, элементы контроля и темы курса по плану учебной дисциплины.
- **Поиск.** По номеру блока («4.3») или по словам («миноры»).
- **Сайт работает офлайн**: прочитанное сохраняется, а кнопка «Скачать все» сохраняет всё сразу.

Нашел ошибку — [открой issue](../../issues/new) или пришли PR.

## Как устроен репозиторий

```text
notes/<course>/NN_mmmDD_slug.md   конспекты лекций (Pandoc Markdown)
theory/<course>.md                теория курса
prep/<course>/krN.md, colloqN.md  подготовка к КР и коллоквиуму
program/<course>.md               план учебной дисциплины
filters/notes.lua                 нумерация блоков, ссылки, вывод в LaTeX и HTML
templates/                        стиль PDF, шаблоны, макросы, список курсов
scripts/                          сборка (build.py) и линтер (lint.py)
web/                              сайт: React + Vite + Bun
context/                          правила для авторов и агентов
```

Конспект — это Markdown с блоками `::: {.definition}`, `::: {.theorem}`, `::: proof` и ссылками вида `[@thm:lec04:laplace]`. Одна сборка делает из него и PDF (xelatex), и HTML для сайта. Номера блоков, ссылки между лекциями и превью ссылок при наведении расставляются автоматически. Линтер следит за схемой: какие разделы обязательны, допустимые типы блоков, есть ли решение у каждой задачи, корректны ли формулы.

Как писать и проверять конспекты: [`context/README.md`](context/README.md). Синтаксис: [`context/markup.md`](context/markup.md). Как устроен сайт: [`web/README.md`](web/README.md).

## Сборка локально

```bash
./scripts/setup.sh                                   # TinyTeX, пакеты TeX Live, Python-зависимости
export PATH="$HOME/.TinyTeX/bin/x86_64-linux:$PATH"
uv run scripts/lint.py                               # проверка конспектов
uv run scripts/build.py                              # build/pdf/… и build/site-data/…
uv run pytest -q                                     # тесты фильтра, сборки и линтера
```

Сайт:

```bash
cd web && bun install
rm -rf public/data && cp -r ../build/site-data public/data && find public/data -name index.html -delete
bun run dev                                          # или bun run build && bunx vite preview
```

CI (`.github/workflows/build.yml`) на каждый PR проверяет линтер и тесты, собирает PDF и выкладывает превью сайта. После мержа в `main` сайт публикуется заново (`pages.yml`).
