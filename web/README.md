# web — сайт конспектов

React 19 + Vite + TypeScript, Tailwind v4, React Router, TanStack Query, KaTeX. Менеджер пакетов и рантайм скриптов — только Bun (`.bun-version`).
Сайт читает данные из `build/site-data` (см. `context/site.md`).

```bash
cd web
bun install
bun data:pull        # site-data и PDF из последнего успешного «Build notes» на main → public/ (нужен gh)
bun dev              # http://localhost:5173
bun run lint:low-memory # полный lint с ограниченным heap Node для тесного dev-окружения
bun run lint         # format → eslint → tsc → knip → jscpd → dependency-cruiser; единственная точка входа, чинит сам
bun run test:e2e     # Playwright: реальный Chromium, управляемые HTTP/WS и внешние сервисы
bun run test         # vitest + testing-library (не `bun test`: это встроенный раннер Bun)
bun run build        # dist/ (+ 404.html и копии оболочки по страницам для GitHub Pages, sw.js и offline-manifest.json)
```

## Тесты и конфигурация

`tests/` повторяет дерево `src/`: unit- и интеграционные тесты лежат отдельно от исходников, общие фикстуры — в `tests/support/`. `tests/e2e/` запускается отдельной командой `bun run test:e2e`; перед первым запуском — `bunx playwright install chromium`. В CI браузерный набор выполняется отдельной задачей. Сбой сохраняет HTML-отчёт и trace в GitHub Actions artifacts; локальные `playwright-report/` и `test-results/` не коммитятся.

Браузерные проверки проходят настоящий UI в Chromium и HTTP/WebSocket-контракт с управляемыми заглушками внешних сервисов. Они не доказывают работу production Turnstile/Telegram/OpenAI; для OpenAI есть opt-in live-тесты backend, а ручные production-сценарии — в `docs/chat-production-checks.md`.

Production-сборка получает `VITE_CHAT_API_URL`, `VITE_TURNSTILE_SITE_KEY`, `VITE_TELEGRAM_CLIENT_ID` из GitHub Actions repository variables. Workflow не содержит запасных значений; `scripts/validate-chat-config.ts` проверяет наличие настроек. Локально значения задаются окружением или игнорируемым env-файлом.

## Устройство

```
src/domain    чистая логика и zod-схемы данных сборки (без React, fetch, DOM)
src/api       загрузка JSON/HTML, запросы TanStack Query
src/shared    UI-кит, ридер конспекта (HTML-фрагмент → React: блоки, ссылки с превью, KaTeX, спойлеры)
src/features  страницы: home (плитка подготовки — нейтральная, акцент по `isHighlighted` из `domain/preps.ts`), course (ряд кнопок «лекция и документы курса», под ним ряд «Подготовка»: предстоящие с датой, затем прошедшие; под таблицей лекций — «Источники» из `domain/sources.ts`), lecture, theory, program («План учебной дисциплины», `/<course>/program`; таблицы — карточками на телефоне), prep (подготовка к КР и коллоквиуму, `/<course>/kr1`, `/<course>/colloq1`; в шапке — PDF читлиста, если он есть; генератор билетов или вариантов, если есть банк)
src/app       роутер, оболочка (скелетоны при переходах)
sw/           service worker: отдельный бандл, из src берёт только domain/offline.ts
```

TypeScript и ESLint проверяют отдельно браузерный код, скрипты Bun, конфигурацию Node, service worker, unit-тесты и E2E. Каждый проект загружает только свои глобальные типы; последовательные процессы ESLint освобождают графы типов между окружениями. Все правила сохраняются. При нехватке памяти в Codespaces с работающим редактором используй `bun run lint:low-memory`: тот же набор проверок, но Node чаще освобождает память и не компилирует JavaScript через JIT. Холодный прогон будет медленнее; CI использует обычный `bun run lint`.

Границы слоёв проверяет dependency-cruiser. Правила линтера — `eslint.config.ts` (строгий набор из iamnalinor/pace-dev: typed strict, sonarjs, unicorn, perfectionist, лимиты размера функций, kebab-case файлов, без default export и `index.ts`); отключённое отключено с причиной.

Генератор билетов (`src/features/prep/tickets/`, логика выбора — `src/domain/tickets.ts`): на странице подготовки с `bank: true` в `courses.json` карточка с подписью `about` и кнопкой «Сгенерировать» встаёт в конец раздела `sec:<prep>:generator` — через `slots` (`CourseDocument` → `FragmentView` → обработчик `section` в `transform.tsx`: React-содержимое в конец раздела по его id). Банк (`data/<course>/<prep>/bank.json`) грузится при открытии страницы; ответ на вопрос (`Reveal` с `lazy`, у кнопки — `aria-label` «Ответ на вопрос N») — только по «Показать ответ»: блоки по `refs` вырезаются из `fragment.html` своих документов (`extractBlock` в `shared/reader/references/extract-preview.ts`, без `id`, у задачи — вместе с ответом и решением, у утверждения в пунктах с `proofs` — со следующим за ним `div.nb-proof`) и рисуются тем же `FragmentView`. На странице КР (`krN`) набор называется вариантом: «Генератор вариантов», «Вариант 2: …». Новый набор объявляется скринридеру (`aria-live`). Набор живёт в состоянии компонента: ни адреса, ни таймера.

**Статус ответа в чате.** Во время ожидания случайный глагол из `src/shared/chat/messages/response-verbs.json` меняется каждые 5 секунд без повторения подряд; после завершения ответа или перехода в фоновый режим таймер удаляется. Слева — терракотовая анимация из 12 кадров с шагом 180 мс (цикл 2,16 с), отключённая при `prefers-reduced-motion`. Все статусы заканчиваются троеточием `…`; «Отвечаю в фоне…» и «Проверяю браузер…» остаются фиксированными.

**Оформление.** Размеры шрифта — только шкала из `@theme` в `src/styles/app.css` (`text-caption` 12, `footnote` 13, `subhead` 15, `body` 17, `title3` 20, `title2` 24, `title1` 32, `large` 40, `display` 56; текст конспекта — 18 px в `prose.css`), стандартные `text-sm` и прочие отключены. Радиусы — `xs`/`sm` для мелочей, `md` (8) у элементов управления, `lg` (12) у карточек и блоков, `xl` (16) у больших поверхностей. Кнопки — три стиля из `src/shared/ui/button.ts`: основная (заливка `ink`), вторичная (тонкая рамка) и сигнальная (оранжевая — только для близкой КР, `isHighlighted`). Блоки конспекта (`shared/reader/block.tsx`) — одна форма: определение, теорема и задача на мягкой подложке своего оттенка без рамки, пример и замечание — текст с тонкой линией слева; на странице теории (`isFlat`) так же выглядят и утверждения, а определения там — обычные абзацы; тип читается по цветному ярлыку, `#номер` блока виден при наведении. Раскрытие (доказательство, решение с ответом в последней строке, «Ответы» на страницах подготовки) — подпись и шеврон, который поворачивается на 90°. На экране уже 1100 px оглавление лекции и курсового документа — плавающая кнопка внизу с текущим разделом и процентом прочитанного, по тапу — шторка (`shared/ui/toc-sheet.tsx`); пока видна плашка «Назад», кнопка скрыта, под футером для неё оставлено место. Боковое оглавление монтируется только на широком экране: `useActiveSection` на странице должен быть один (первый, кто увидел переход по якорю, закрепляет цель), поэтому шторка рисует `TocList` со своим состоянием.

Фрагмент конспекта разбирает `html-react-parser`: `div.nb` → `Block`, `a.ref` → `RefLink` (якорь по номеру + превью блока при наведении, по тапу на телефоне), `span.math` → KaTeX, `nb-proof` → сворачиваемое доказательство, `nb-answer`/`nb-solution` → спойлеры внутри карточки задачи.

Поиск (`src/shared/search/`, логика — `src/domain/search.ts`): поле прямо в верхней панели (без модального окна): на телефоне панель остаётся одной строкой (логотип, курсы, лупа), тап по лупе раскрывает поле поверх строки с «Отмена» (свёрнутое поле — `sr-only`, а не `hidden`: фокус ставится в том же тапе, и iOS поднимает клавиатуру), результаты — под панелью во всю ширину; переключатель темы на телефоне — в подвале; на десктопе — выпадающий список под полем. ⌘K / Ctrl+K или «/» ставят фокус в поле, Esc сворачивает. Номер («4.3») ищется точно по `index.json`, слова — по `data/search.json` (весь текст без ответов к задачам и без копий блоков в теории, ~1,6 МБ; грузится при первом касании поля, а на Wi-Fi — сам через 3 с после загрузки страницы (`canAutoDownload`), дальше из кэша service worker; «Скачать все» его не сохраняет): совпадение с началом слова (TeX формул не ищется), у слов длиннее 4 букв отбрасываются 2 последние буквы («миноры» → «мино»), слово в заголовке весит больше, чем в тексте. Сразу рисуются 12 результатов, остальные — по кнопке «Показать ещё»; формулы KaTeX кэшируются по исходнику (`tex-math.tsx`), поэтому нажатие клавиши не перерисовывает одни и те же формулы заново. Горячие клавиши проверяются по `event.code`: работают и в русской раскладке.

**Поисковики и LLM.** `scripts/spa-fallback.ts` (теги и тексты — `src/domain/seo.ts`) кладёт в копию оболочки каждой страницы `canonical` и `og:url` на `https://hse.nalinor.dev/<путь>/`, `<link rel="alternate" type="text/markdown">` на исходник страницы в репозитории (raw GitHub), картинку превью ссылок (`og:image` 1200×630 + `twitter:card` `summary_large_image`: у главной — `public/og/site.png`, у страниц курса — `public/og/<course>.png`; картинка главной — без символов курсов; картинки закоммичены, перерисовать после смены названия, лектора или символа курса — `bun og:images`, нужен Chromium Playwright 1.64), `<link rel="alternate" type="text/plain">` на `llms.txt`, JSON-LD (`WebSite` на главной, `BreadcrumbList` на остальных) и текстовый фолбэк для клиентов без JS (LLM-фетчеры, конвертеры HTML → Markdown): заголовок, описание, полная ссылка на Markdown этой страницы, PDF, `llms.txt` и репозиторий, а у лекции, теории, программы и подготовки — ещё и весь текст страницы (`data/<путь>/fragment.html` в `<article>`: формулы — LaTeX-текстом в `\\( \\)` / `\\[ \\]`, картинки — из `data/<путь>/fig/` с `loading="lazy"` (браузер с JS скрытые ленивые картинки не качает), заголовки на уровень ниже `<h1>` страницы; `fallbackArticle` в `seo.ts`), так что поисковики, превью и LLM читают текст одним запросом. Копии страниц в предзагрузку service worker не входят, поэтому текст в них офлайн-кэш не раздувает. Фолбэк лежит прямо в `#root`, а не в `<noscript>`: конвертеры выкидывают `<noscript>` вместе со ссылками. React заменяет его при монтировании, а до того браузер с JS его не показывает (`<style>` в `index.html` по `data-theme`, который ставит inline-скрипт темы). На странице курса в фолбэке ещё и ссылки на Markdown всех её лекций и документов. В `404.html` — «Страница не найдена» со ссылкой на `llms.txt`, без `canonical`. Рядом пишет `sitemap.xml` (главная и все страницы из копий), `robots.txt` (всё разрешено + ссылка на sitemap) и `llms.txt` ([llmstxt.org](https://llmstxt.org): где лежат исходники и список страниц; ссылка ведёт на Markdown-исходник, адрес страницы — после описания). В `offline-manifest.json` эти три файла не входят. Service worker на любую навигацию отдаёт оболочку главной, поэтому `canonical` и `og:url` открытой страницы держит `useCanonicalUrl` (`src/shared/ui/canonical-url.ts`, в `AppShell`): иначе «Поделиться» отправляло бы ссылку на главную. Описание главной — `SITE_DESCRIPTION` в `seo.ts`, тот же текст в `index.html` (проверяет тест). Подтверждение прав в Google Search Console и Яндекс Вебмастере — не в коде (DNS-запись домена или мета-тег, если понадобится).

Google Analytics (GA4) вставляет плагин в `vite.config.ts` только в `vite build`: в `bun dev` и тестах счётчика нет. Переходы внутри SPA GA4 считает сам («Enhanced measurement → page changes based on browser history events»).

Шрифт — HSE Sans (`src/styles/fonts/`, 400/600/700/900; курсива у шрифта нет, браузер наклоняет сам), формулы — KaTeX.

## Офлайн

`scripts/build-sw.ts` после `vite build` считает хэш каждого файла в `dist/` и пишет `offline-manifest.json`: оболочка (`index.html`, JS, CSS, woff2) и общие данные (`courses.json`, `index.json`, `katex-macros.json`) — `precache`, каждая лекция, теория, программа курса, подготовка курса — документ из нескольких файлов (вид — `kind`: `notes`, `theory`, `program`, `prep`; id курсовых документов — `COURSE_DOCS` в `src/domain/course-docs.ts`). В `sw.js` вшита только версия манифеста, поэтому проверка обновлений раз в минуту стоит ~3 КБ.

- install: скачивает изменившиеся файлы оболочки в промежуточный кэш, старая версия пока продолжает работать;
- activate: удаляет из кэша файлы, чей хэш не совпал с новым манифестом (конспект перезагрузится, только если правда поменялся), переносит новые;
- fetch: навигация (открытие сайта, перезагрузка) на страницу, которую знает манифест (главная, курс, документ; `knownPages` в `domain/offline.ts`) → `index.html` из кэша, если в сети нет новой версии: воркер проверяет `sw.js` (`registration.update()`, ~3 КБ, до 1,5 с; `sw/update-check.ts`; без сети — не проверяет). Поэтому полная загрузка с сетью уже не мгновенная: она ждёт один запрос `sw.js`. Есть новая версия или страница незнакомая (новая лекция свежего деплоя) — страница из сети (4 с на заголовки, тело копии с текстом лекции докачивается без таймаута): ответ 200 от Pages значит, что она из нового деплоя. Её отдаём как есть, все запросы этой вкладки идут в сеть мимо старого кэша, и воркер сразу проверяет обновление. Вкладка спрашивает воркер (`is-fresh`) и при первой смене воркера не показывает плашку: она уже работает на новом коде (сама включает ждущий воркер или молча принимает тот, что включила другая вкладка). Включает не сразу, а когда страница загрузилась и затихла (`whenPageSettled`): `skip-waiting`, пока страница ещё грузится через старый воркер, заставляет Chrome остановить его посреди запросов, и новый воркер может так и не включиться — следующая загрузка виснет. До переключения старый воркер ничего не сохраняет, поэтому «Скачать все» и фоновое скачивание ждут его (`whenOnOwnWorker`); клик по «Скачать все» включает воркер сразу. Офлайн, таймаут, 404 → закэшированная оболочка, как раньше; известные файлы — из кэша, иначе из сети с сохранением; открытая лекция сохраняется целиком, вместе с рисунками ниже по странице; PDF — только сеть.

Футер показывает «Офлайн: N из M конспектов» (считаются только копии с актуальным хэшем, счётчик растёт по мере скачивания) и кнопку «Скачать все» с объёмом того, что осталось скачать (gzip-размер файлов документов — поле `sizes` манифеста, его считает `build-sw.ts`; сейчас всего ~2,6 МБ). Новая версия — плашка сверху (`src/shared/offline/`). Пока она висит, переход по ссылке на другую страницу — не смена маршрута в старом коде, а полная загрузка новой версии (`useUpdateOnNavigation`: `useBlocker` роутера, переключение на ждущий воркер, `location.assign`). Назад/вперёд, якоря на той же странице и переходы без сети остаются в старом коде: перед переключением вкладка проверяет страницу запросом `HEAD`, иначе новый воркер удалил бы устаревшие офлайн-копии, а новых без сети не скачать.

**Фоновое скачивание.** На компьютере — всегда (если не включена экономия трафика), на телефоне — если соединение точно Wi-Fi или кабель: сайт сам скачивает все документы, как «Скачать все», но в фоне; в футере — «Сохраняем остальные в фоне…».

- Правило (`src/domain/connection.ts`): `saveData` выключен и `effectiveType` не `2g`/`slow-2g`; дальше — по устройству. На телефоне и планшете — только если браузер прямо говорит `type` = `wifi` или `ethernet` (Chromium отдаёт `type` только на Android и ChromeOS; Firefox и Safari API не имеют — тогда нет). На компьютере (`(hover: hover) and (pointer: fine)`, `isDesktopDevice`) неизвестный тип сети тоже подходит: десктопный Chrome, Firefox и Safari качают в фоне (решение владельца, ноябрь 2026); явный `cellular` и прочие лимитные типы по-прежнему останавливают загрузку. Отказаться — включить в браузере экономию трафика (`saveData`).
- Не мешает чтению (`src/shared/offline/background-download.ts`): старт через 5 с после `load` в idle-период; файлы по одному, каждый — в idle-период, когда у страницы нет своих запросов (`isFetching` TanStack Query); `fetch` с `priority: "low"` и заголовком `x-offline-background`, по которому воркер сам идёт в сеть с низким приоритетом и не докачивает остальные файлы документа параллельно. Файлы сохраняет тот же воркер, в тот же кэш.
- Соединение стало `cellular` или включили `saveData` (событие `change`) — загрузка сразу прерывается и продолжится, если снова будет Wi-Fi. Во скрытой вкладке продолжается. Закончилась (или упала) — в этой вкладке для этой версии больше не запускается; нажатие «Скачать все» забирает работу на себя (4 потока, с прогрессом). В `bun dev` воркер не регистрируется; проверять — `bun run build` и раздать `dist/` статикой.

## Деплой

`.github/workflows/pages.yml`: после успешного «Build notes» на `main` берёт его артефакты `site-data` и `pdf`, собирает сайт с `BASE_PATH=/<repo>/` и публикует на GitHub Pages. Проверки фронта — `.github/workflows/web.yml`.

### Прямые ссылки на Pages

У Pages нет SPA-фолбэка: неизвестный путь отдаёт `404.html` со статусом 404. Поэтому `scripts/spa-fallback.ts` после сборки:

- копирует оболочку (`index.html`) в `404.html`: любой путь запускает роутер;
- кладёт копию оболочки в `dist/<course>/`, `<course>/theory/`, `<course>/program/`, `<course>/krN/` и `<course>/<week_id>/index.html` (только для существующих документов) с заголовком, description, og-тегами, canonical и JSON-LD этой страницы. Такая ссылка отдаётся со статусом 200 и со своим `<title>`, превью ссылок и поисковики видят настоящую страницу.

Оговорка: копии лежат как `каталог/index.html`, поэтому адрес без слэша (`/algebra/theory`) Pages сначала редиректит на `/algebra/theory/` (301), потом отдаёт страницу. Вариант `<route>.html` без редиректа не проверялся: неясно, как Pages ведёт себя, когда рядом лежат `algebra.html` и каталог `algebra/`, поэтому оставлен каталог. Ссылки внутри сайта идут через роутер и перезагрузки не вызывают.

**Переименованные лекции.** Slug в `week_id` меняют, когда он перестал описывать лекцию (`context/markup.md` §1). Копии под старым адресом нет, поэтому Pages отдаёт `404.html` (статус 404, поисковики видят 404), а роутер перенаправляет на лекцию с тем же номером: страницу — `features/lecture/page.tsx` (`resolveLecture`), PDF `/pdf/<course>-<week_id>.pdf` — маршрут `pdf/:file` (`LegacyPdfRedirect`, `location.replace` на текущий файл). Вкладка, открытая на старой версии сайта, ведёт по старым `week_id` к удалённым файлам, пока не примет обновление: `RouteError` в этом случае показывает кнопку «Обновить» (тот же `applyUpdate`, что у баннера).

Копии оболочки не входят в `offline-manifest.json` и service worker их не кэширует: любая навигация в его области отдаётся из закэшированного `index.html`. Смоук-тест `pages.yml` проверяет, что `/algebra/theory/` отдаёт копию с `<title>Алгебра: теория`, а `/calculus/program/` — с `<title>План учебной дисциплины: математический анализ`, а не `404.html`.
