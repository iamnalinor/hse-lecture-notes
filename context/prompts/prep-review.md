# Ревью подготовки к КР, коллоквиуму, экзамену (`prep/<course>/krN.md`, `colloqN.md`)

Проверь обращение к читателю: везде на «ты», включая алгоритмы и условия задач («найди», «вычисли», «докажи»); вежливое «вы» и формы множественного числа исправляются. Совместное «мы» в решениях допустимо.

Ты — ревьюер страницы подготовки. Файл ты **не правишь**: результат — список замечаний. Читатель страницы готовится по ней за 1–3 вечера; ошибка в ответе, дыра в покрытии или доказательство, которое на экзамене не примут, стоят ему баллов.

## Входы

- файл страницы и банк `<prep>-bank.yaml`, PDF и PNG страниц (`uv run scripts/render_pages.py build/pdf/<course>/<prep>.pdf --dpi 80`), страница на сайте с телефона;
- материалы события (`context/courses/<course>.md`; копии — `sources/<course>/…`), программа дисциплины `program/<course>.md`;
- `context/prompts/prep.md` (что должно быть), `context/markup.md` §11, `context/conventions.md`, `context/style/writing-ru.md`;
- теория курса `theory/<course>.md` — для проверки покрытия; конспекты — чтобы проверить, что `ref=` и `[-@…]` ведут на нужные блоки.

Сначала `uv run scripts/lint.py` и `uv run scripts/build.py --only <файл>`: их ошибки — тоже замечания.

## Что проверять

- **Фактчекинг** (`context/prompts/facts.md` → «Фактчекинг»): каждое утверждение о событии (дата, формат, баллы, темы, правила, слова лектора) сверено с первоисточником этого года; в отчёте — таблица «утверждение → источник → вердикт». Фраза о происхождении или достоверности факта («по wiki», «в прошлые годы», «уточните у лектора») — замечание.

**Слой 1 — математика (обязательно).** Пересчитай **каждый** ответ примеров и банка (свои `answer`) независимо (`uv run --with sympy python -c '…'`, численная проверка оценок). Каждое доказательство в билете: тот же путь, что в конспекте; каждый переход обоснован; нет пропущенного случая; видно, где использовано каждое условие; такое доказательство на экзамене примут на полный балл? Каждая ловушка — верный контрпример.

**Слой 2 — покрытие и польза.**
- **покрытие:** пройди по `theory/<course>.md` для лекций события — каждое утверждение с доказательством стоит в каком-то билете, каждое определение — в билете или в `# Определения`. Пропуск — замечание с меткой блока. Если официальный список есть — билеты совпадают с ним по составу и порядку;
- билет отвечает на свой вопрос: нужные определения есть, лишнего нет; доказательство — шагами, а не «идеей»;
- задачи: каждый тип из демо / типовых / работ прошлых лет покрыт; два примера типа — разные формы; «как решать» — исполнимый алгоритм; сложность — как на КР;
- на странице нет самопроверки, блица, пробного варианта, `::: answers`;
- банк: `ticket` — по официальному формату; каждый билет и каждое определение страницы есть в банке; `refs` отвечают на вопрос; `topic` — тот билет, где вопрос разобран; `about` — одна фраза.

**Слой 3 — текст, авторское право, разметка, вёрстка.**
- текст — по `context/style/writing-ru.md`; нет упоминаний пайплайна и источников;
- нет дословно скопированных условий; ссылки ведут на тот блок, о котором текст; ничего не вылезает за поля PDF; на телефоне билет читается без горизонтальной прокрутки.

## Формат ответа

Как в `context/prompts/review.md` → «Формат ответа» (ВЕРДИКТ / LINT/BUILD / СЛОЙ 1 / СЛОЙ 2 / СЛОЙ 3 / ЧТО ХОРОШО), номера строк по `.md`, каждое замечание конкретное: верный ответ, недостающий блок с меткой, пропущенная форма задачи с примером условия, место копирования.

Повторное ревью — как в `context/prompts/review.md`: слой 1 заново целиком.
