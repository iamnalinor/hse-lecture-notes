# Как добавить новый конспект: полный путь

Инструкция для агента, которому дали задачу «напиши конспект лекции N по курсу X», и для оркестратора, который раздаёт такие задачи. Все пути — от корня репозитория.

Объём в моменте: написаны все лекции семестра (М1 + М2): прошедшие — по лекциям, будущие — прогнозом. По мере того как лекции проходят, прогнозы нормируются (конец файла).

## 0. Окружение (один раз за сессию)

```bash
./scripts/setup.sh                     # TinyTeX + пакеты TeX Live + uv sync (идемпотентно, ~3 мин в первый раз)
export PATH="$HOME/.TinyTeX/bin/x86_64-linux:$PATH"
./scripts/fetch_sources.sh             # публичные репозитории-источники → sources/ (не коммитится)
uv run pytest -q                       # пайплайн жив
```

## 1. Найти лекцию в плане курса

Открой `context/courses/<course>.md` → «Расписание и план семестра».

- **Лекция есть в таблице.** Возьми `week_id`, дату, тему и режим, раздел «Лекции подробно» (если есть) и источники.
- **Лекции нет** (новая неделя, перенос):
  1. Дата: день лекции курса из `context/schedule.md`. Переносы и праздники сверь с Google Calendar «Education», если есть доступ. Перенос на другой день недели внеси в `templates/courses.json` → `date_exceptions`, иначе линтер не пропустит дату.
  2. Номер: следующий по порядку. Недели сессии не считаются.
  3. `week_id` — по `context/markup.md` §1. Slug описывает содержание лекции. Разошёлся с реальными темами (нормировка, перенос тем) — переименуй файл и строку плана: старые адреса сайт находит по номеру лекции (`markup.md` §1).
  4. Добавь строку в таблицу плана со статусом «пишется».

## 2. Выбрать режим и собрать источники

| Режим | Когда |
| --- | --- |
| По лекции (`lecture`) | Лекция прошла, есть материалы именно этой лекции 2026: запись или субтитры, фото доски, тезисы лектора, конспект однокурсника |
| Прогноз (`forecast`) | Лекции ещё не было, или от неё нет материалов, кроме общего плана курса |

Только план или программа курса — это не материалы лекции: такой конспект остаётся прогнозом. Режим и источники записываются **только** в таблицу плана `context/courses/<course>.md`: в конспекте, PDF и на сайте их нет, читатель видит одинаковые конспекты.

Источники перечислены в `context/sources.md` и разделе курса `context/courses/<course>.md`. Скачай нужное в `sources/<course>/…`: Google Drive — через Drive-коннектор, веб — через WebFetch, репозитории — `fetch_sources.sh`. Материалы этого года важнее прошлогодних: порядок тем, обозначения и объём берутся из 2026.

**Прогноз калибруется по уже прочитанным лекциям 2026.** Прошлые годы и план курса говорят, *какие* темы будут, а где лектор их начнёт и сколько успеет, говорят только опубликованные лекции этого года. Перед прогнозом:

1. Проверь, не появились ли новые материалы: плейлист или канал курса, wiki, Drive-папку. Появилась запись этой лекции — это уже режим `lecture`.
2. Возьми материалы последней прочитанной лекции (запись, субтитры, тезисы лектора) и найди, где лектор остановился и что анонсировал на следующую пару. Прогноз начинается ровно с этого места: что прошло, в прогноз не входит. Исключение — недоконченное доказательство: его окончание дописывается в конспект прошлой лекции (`prompts/generate.md`, шаг 2), а прогноз начинается после него.
3. Объём подбери по реальному темпу лектора (сколько он успевает за пару в лекциях 2026), а не по прошлогоднему конспекту. Обозначения, стиль доказательств и характерные примеры тоже бери из лекций 2026.
4. Если план курса (`context/courses/<course>.md`) расходится с прочитанными лекциями, верь лекциям и поправь план.

**Насколько верить прошлым годам** — зависит от того, сменился ли лектор:

- **Алгебра и дискретная математика** — лекторы те же, что в прошлые годы (Михайлец, Дашков). Порядок тем, темп, деление материала по лекциям, обозначения и примеры прошлых лет — надёжный ориентир, особенно там, где лекций 2026 ещё нет (новый модуль, начало семестра). Отличия 2026 от прошлых лет, уже замеченные по прочитанным лекциям (например, сдвиг темпа), переноси вперёд.
- **Матанализ** — лектор сменился (2023/24 — Эрлих, 2026/27 — Бельдиев). Конспект 2023/24 говорит, *какие* темы бывают и как их можно доказывать, но не где лектор начнёт, сколько успеет и какие обозначения выберет. Опора — ПУД и таблица планирования 2026/27 и лекции 2026; прошлогодний порядок и объём — только как подсказка, с оговоркой в плане курса.

## 3. Прочитать перед тем, как писать (в этом порядке)

1. `context/conventions.md`: общая часть и раздел своего курса. Конспект пишется в обозначениях курса, а не учебника.
2. `context/recommendations.md` целиком: Р1–Р32, запреты, чеклист.
3. `context/markup.md`: синтаксис.
4. `context/prompts/generate.md`: шаги генерации.
5. Предыдущие конспекты курса `notes/<course>/*.md`: последний — целиком, ещё хотя бы один и все, на которые будешь ссылаться. Что уже есть в них (определения, теоремы, доказательства, примеры), на то ссылайся и не повторяй (Р28).
6. Метки, которые уже есть: `uv run scripts/build.py --no-pdf --no-html`, затем смотри `build/index.json` → `labels.<course>`.

## 4. Написать

```bash
cp templates/note-skeleton.md notes/<course>/<week_id>.md
```

Дальше по `context/prompts/generate.md`. Все новые термины идут в глоссарий, каждый навык из «После прочтения ты сможешь» получает задачу в самопроверке.

## 5. Проверить машиной

```bash
uv run scripts/lint.py notes/<course>/<week_id>.md          # 0 ошибок; предупреждения разобрать
uv run scripts/build.py --only notes/<course>/<week_id>.md  # PDF + HTML без ошибок
```

Сборка падает на неизвестной ссылке, дубликате метки и ошибке LaTeX: сообщение указывает строку в `build/tex/<course>/<week_id>.tex` и лог. Предупреждение `overfull box` означает, что формула или строка вылезла за поле. Его нужно исправить: перенести формулу, разбить её через `aligned` или уменьшить рисунок.

## 6. Посмотреть глазами

```bash
uv run scripts/render_pages.py build/pdf/<course>/<week_id>.pdf --dpi 90
```

Открой PNG страниц (инструментом чтения изображений) и проверь рамки, колонтитул, формулы, рисунки и подписи, переносы. HTML-версия: `build/site-data/<course>/<week_id>/index.html` (KaTeX грузится с CDN). Скриншот можно снять Playwright: Chromium лежит в `/opt/pw-browsers/chromium`.

## 7. Чеклист, теория курса, план

1. Пройди чеклист из конца `context/recommendations.md`. Невыполненный пункт означает переписать место, а не оговорку в конце.
2. Обнови `theory/<course>.md` по `context/prompts/theory.md`: добавь или замени раздел «Лекция N — тема».
3. В `context/courses/<course>.md` поставь статус «написан, ждёт ревью».

## 8. Ревью

Отдельный агент, не видевший генерации, проверяет конспект по `context/prompts/review.md`. Ему передают путь к `.md`, к PDF и к PNG страниц. Писатель исправляет замечания, ревью повторяется, пока есть замечания слоя 1 (математическая корректность); слой 1 — обязательное условие мерджа. Ответы на замечания и споры живут в отчёте или в PR, в конспект не попадают.

После ревью статус в плане курса: «готов (ревью пройдено)»; режим остаётся в колонке `basis`. Это внутренние пометки, наружу они не выходят.

## 9. Коммит

```bash
git add notes/<course>/<week_id>.md theory/<course>.md context/courses/<course>.md
git commit -m "<course>: лекция N — <тема>"
```

PDF и `build/` не коммитятся: их собирает CI (`.github/workflows/build.yml`: линт, тесты, `build.py --strict` — overfull box и неизвестная ссылка валят сборку), PDF доступны как artifact и в релизе `latest`; сайт публикуется после сборки `main` (`context/site.md`).

# Как перевести прогноз в конспект по лекции (нормировка)

Когда лекция, написанная прогнозом, прошла и появились её материалы, работай по `context/prompts/normalize.md`; проверка, теория курса, ревью и коммит — как в §5–§9 выше. Ревью отдельным агентом (§8) после нормировки обязательно для каждой нормированной лекции, самопроверка его не заменяет. Оркестратор, который раздаёт нормировки, запускает ревью каждой из них до коммита.
